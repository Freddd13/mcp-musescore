# 隐藏字体：完整对象和未展示字符复核

2026-10-19。当前仍为Study 0.500，本轮没有改变Music／Text字形、尺寸或安装配置。此前269个隐藏字体组只看过少量全对象选样；这轮扩大到其全部对象，并补上旧清点因空白处理而漏掉的字符。

## 实际检查范围

读取57份源PDF中全部269组、4,273个文字对象，逐项记录原件SHA、页码、对象索引、字体、变换和实际源字符；字体程序未读取或保存。保留完整字符串，不把控制编码的字母、音乐组合或沿滑音旋转的文字拆成猜测的SMuFL字形。

- 3,773个对象单独渲染可见；500个未显示的对象另外验证，见下。
- 2,232个不同的字体句柄／字符串／方向代表已全部审视，压紧后的八张联系图没有省略代表项。映射错误／空字符串另外按实际图像区分，避免把同一提取文本误当同一形状。
- 按组和本轮字体句柄序号区分，共4,111个源字符键，均在所审视的代表中有位置；合并句柄后为3,866个组／码位键。句柄序号只是此次扫描的局部分组，不能作为跨运行或跨PDF的字体身份。
- 旧3,737个组／码位键全部仍在；新增129个：118个组中的实际空格、六组中的U+0000，以及H112的五个控制编码键。

每个对象都经过渲染尝试和归属记录，不等于每个相同字符串在所有大小下都独立做过语义及印刷认证。联系图为识别而拟合图像，不能用来评价实际符号尺寸。原生大小继续见[TEXT_SIZING](TEXT_SIZING.md)。

实现：[catalog_hidden_font_objects.py](catalog_hidden_font_objects.py)。全部对象`dist/hidden-all-objects-169/objects.json`；八张完整联系图及布局对应`dist/hidden-compact-171/`。

## 为什么旧字符清点会漏掉普通字母

A057的H112是一套控制编码普通文字字体。完整对象显示l.h.、r.h.、cresc.、rit.、dim.、a tempo等词；提取码却是U+0001到U+000F。旧索引对字符串调用空白裁剪和`isspace()`，会误跳过如下实际源字符：

| 提取码 | 本字体中的实际作用 |
| --- | --- |
| U+0009 | t |
| U+000A | d |
| U+000B | m |
| U+000C | a |
| U+000D | 词间空格 |

所以“Unicode把它叫制表／换行”不能证明它在此PDF中是排版空白。依据完整对象读出的15字符对应保存在[source/reviewed_catalog_roles.py](source/reviewed_catalog_roles.py)；用实际源字符解读该组全部对象，得到的十种词组与已看图像一致。它们都是普通表达文字，没有为控制码另加音乐字形。

此次保留旧`corpus-v2`清点作为固定证据，本轮全对象补扫已经补偿上述遗漏。下一轮修正全目录索引的字符取得方式，并写入新目录，不能覆盖旧哈希所指的材料。PDFium生成间隔与实际源字符仍分开，相关机制见[ENCODING_VARIANTS](ENCODING_VARIANTS.md)。
