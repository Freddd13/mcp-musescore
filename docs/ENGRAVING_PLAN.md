## 1. 用户目标与工作边界

这条线研究的是净书本身：掌握规范，分析出版谱为什么这样安排、这种安排为什么有利于阅读和演奏，再为自动净书建立可解释的判断依据。不能用“换字体”“抄参数”或“增加 MCP 接口”代替这项研究。

目标读者是实际弹奏钢琴的人。质量判断包含音高与节拍辨认、声部和标记归属、视线连续性、乐句组织、视觉均衡、翻页条件与实际打印可读性；不以页数减少或每页塞入更多系统作为单独成功标准。

- 本线将音乐字体作为排版输入，暂不制作、安装或改写字体。此前选择的字体渐进改造方案交由分支对话处理。
- 原 PDF、MSCZ 只读；任何替代排法试验使用独立副本，不操作用户当前 GUI 乐谱，不覆盖原件。
- 保留音高、时值、声部、演奏参数和标记的语义范围。即使某种语义改写更好看，也只能提出建议，不能作为纯净书动作自动执行。
- 优先插件方案。只有经过案例验证且插件能力不足，才考虑最小 MuseScore 本体改动，并遵循 AGENTS.md 的日志、用户指南、提交要求。

## 2. 当前认识：证据、解释与未知分开

### 2.1 已完成的探索

上一轮读取了 7 份官谱的元数据与字体，并渲染其中若干样本；检查了用户 PDF 全部 8 页、release5 工程副本、6 份本地 MSS 和相关布局源码。重点新官谱样本使用 Chaconne，用户成品主要音乐字体为 Leland。PDFium 元数据不能证明参考谱采用了哪款制谱软件。

实测主要参考谱的五线谱高度约 6.0 mm，用户成品约 6.28 mm；谱线物理宽度都约 0.14 mm。一个官谱连梁样本约 0.48 sp，当前用户工程有效 beamWidth 为 0.50 sp。这些证据不支持“把所有线条减细即可接近官谱”。sp 指相邻谱线距离，五线谱高为 4 sp。

用户成品第 2 页的一些上下谱表空隙比参考谱更大。但不同作品的音域、声部、弧线和标记不同，不能用页密度比较直接证明某个排版引擎更好。

既有隔离试验发现：只换 Finale Maestro/Text，release5 副本从 8 页变为 9 页；只调整独立 Tie 粗细，部分过重延音线明显改变。它们分别说明字体度量会影响分页，以及视觉问题可能来自样式兼容而非字形。试验没有证明最佳字体或最终净书方案。

### 2.2 机制与限制

净书不依赖 MCP。MuseScore 原生引擎绘制谱面，插件提供读取和操作，MCP 是 Codex 的调用通道。

现有 MCP 可以读取音乐结构，但没有完整的净书样式、页面、局部几何和原生预览接口；VexFlow 预览不画延音线与连音括号，不能作为净书验收图。原生 Plugin API 已提供样式、位置、外框、小节拉伸、连梁和部分连线控制属性，但“属性存在”不等于遍历、单位、撤销及复杂谱例已经验收。

MuseScore 已处理部分凹形／重复音型水平连梁、倾斜厚度补偿和多层连梁间距，不应把这些重复实现当作借鉴 Dorico 的新增目标。后续需要找具体失败情境。

未完成：系统掌握全部净书规范、全谱逐处分析、同曲双软件比较、可重复的净书规则库、自动净书实现。制谱者的实际意图不能仅由成品 PDF 证明。

## 3. 规范体系与来源

### 3.1 三类依据

| 类型 | 内容 | 后续处理原则 |
| --- | --- | --- |
| 音乐语义与必要约束 | 音高、时值、声部身份、同步拍点、标记范围、信息归属 | 保护原意；语义存在歧义时报告，不擅自猜测修改 |
| 有上下文的净书惯例 | 连梁与节拍、符干方向、休止位置、连线端点、标记层次、提示性记号 | 查明适用条件、例外及相互冲突；不能全部当作硬约束 |
| 出版风格与个人偏好 | 字体、黑度、文字体系、疏密、标题和末系统处理 | 明确为风格目标，允许多个合理方案 |

### 3.2 学习顺序

1. 记谱基础：节拍可读性、连梁分组、时值拆分、声部与休止、变音记号、延音线和连音。
2. 钢琴情境：多声部、手与谱表的关系、跨谱表、换谱号、八度线、指法、踏板及复杂织体。
3. 局部净书：符干／连梁、弧线、和弦／变音列、附点、力度／渐强／文字及其层次。
4. 系统与页面：光学间距、相对密度、大谱表内部空间、系统留白、乐句换行和翻页。
5. 规则冲突：区分优先级，研究满足同一音乐语义的多个合理布局。

### 3.3 核查来源与阅读状态

- Elaine Gould《Behind Bars》：此前核查[官方目录](https://behindbarsnotation.co.uk/contents/)与[公开样章](https://behindbarsnotation.co.uk/contents/sample_pages.pdf)；本轮找到用户OneDrive的696页全文，定向阅读钢琴声部/休止/跨谱表、连音、装饰音/震音、踏板、反复、间距与翻页，并复核20个图页。具体页码与尚未读处见 [阅读笔记](engraving/BEHIND_BARS_NOTES.md)。未通读全书，全文索引不等于逐页掌握。
- Ted Ross 的连梁规则：现阶段通过 [Dorico 官方连梁设计说明](https://blog.dorico.com/2015/03/development-diary-part-10/)了解其讨论与限制；没有将二手转述标成原书直接核实。
- LilyPond：[光学间距](https://lilypond.org/doc/v2.25/Documentation/essay/optical-spacing)、[候选布局评价](https://lilypond.org/doc/v2.25/Documentation/essay/beauty-contests)、[真实净书基准比较](https://lilypond.org/doc/v2.25/Documentation/essay/improvement-by-benchmarking)。这是机制与算法参考，不是所有出版机构共同遵循的规范。

## 4. 参考谱分析方法

### 4.1 固定分析链

每个案例按以下顺序记录：

**音乐上下文 → 读者任务 → 参考排法 → 规范依据 → 阅读与视觉收益 → 替代方案代价 → 例外 → 可验证的判断。**

“为什么这样排”必须区分三层：可直接观察的效果、规范／机制支持的解释、对制谱者意图的推测。不得把最后一层写成已证实事实。官谱可以包含不理想或依赖人工判断的地方，不因其是官谱而默认最优。

### 4.2 首批案例安排

五组问题各选至少两个情境，首批不少于 10 个案例：

| 问题组 | 首批取材 | 重点解释 |
| --- | --- | --- |
| 节拍与声部组织 | IRIS OUT 第 2 页的重复织体；用户第 2 页的多声部片段 | 连梁／符干／休止如何组织阅读，是否暗示错误重音或声部关系 |
| 横向阅读 | Sincerely 第 2 页不同织体；用户第 2 页密集与稀疏片段 | 时值空间、符干方向、变音记号及小节线如何改变感知间距 |
| 标记归属与层次 | Sincerely 第 2 页八度线／长连线；用户第 6 页首系统 | 为什么某种避让保持归属，另一种虽无碰撞却破坏层次 |
| 系统与页面组织 | Idol、Shirushi 的完整相邻页；用户换行与页末 | 换行、页密度和留白的可观察效果；翻页意图需要另行音乐核查 |
| 整体一致性 | IRIS OUT 重复音型；Sincerely 相邻系统与用户对应片段 | 同类内容的处理是否一致，哪些例外由音乐内容引起 |

分析与本地路径对应见第 8 节。不要将不同音乐直接当作布局算法的因果对照。

### 4.3 受控验证

需要验证解释时，在同一音乐、副本和宿主版本上只改变一个因素：字体、谱表／版心、横向间距、垂直间距、连梁、弧线或局部标记。明确是否保留旧手工偏移与换行，它们是实验条件而非可忽略背景。

原生 Windows 导出用于本机验证。既有 offscreen 实验曾产生系统字体替换和中文方框，不能用其结果评价真实字体和制谱质量。检查完整页面、局部同 sp 比例和实际打印大小，三者用途不同。

## 5. 规则卡片与案例格式

研究输出应能支持实现，而不是只留下审美形容词。规则卡片固定记录：

- 编号、问题类别与状态（待核实／已核实条件／已完成副本验证）。
- 触发情境、所需音乐上下文、保护的语义与人工意图。
- 来源和依据；是惯例、机制还是风格偏好。
- 候选动作、各自收益与代价、优先级、例外与冲突。
- 所需数据与单位、实现可行性和当前未知。
- 对应正例、反例、边界例以及验收结果。

首批规则方向：

| 编号 | 已有依据与目标 | 不能机械化的部分 |
| --- | --- | --- |
| E-HSP-001 光学间距 | LilyPond 展示符干方向和小节线影响感知间距；评价视觉节奏而非只比较符头中心距离 | 多声部必须保持共同拍点，不能逐声部独立挪动导致失去同步 |
| E-OTT-001 标记层次 | Gould 样章讨论八度线与其他标记的外围／内层关系及阅读原因 | 持续范围、系统边界和空间约束不同，不能一律固定 Y 坐标 |
| E-BEM-001 连梁走势 | 结合外侧音、内部音型、谱线落点及符干空间，参考 Gould 样章和 Dorico 说明 | 跨谱表、多声部、装饰音和人工分组分别核查，不擅自改分组 |
| E-PNO-001 大谱表组织 | 参考谱和 Dorico 机制支持分别评价内部空隙与系统间留白 | 6–7 sp 等测量范围不是全曲硬标准，内容空间需求优先 |
| E-TIE-001 旧谱样式风险 | release5 在既有 Evolution 宿主中缺独立 Tie 设置时粗细发生可操作差异 | 未完成原版 3.6.2 双引擎回归；不把所有曲线差异归为同一兼容缺陷 |

以上是研究入口，不表示已交付完整自动规则。外框重叠只能提示候选问题；光学轮廓、允许接触和归属需要进一步判断。

## 6. 从研究到自动净书的阶段

### 阶段 A：规范与案例（当前）

完成上述 10 个首批案例和逐条来源核查，形成规范索引、规则卡片与带解释的案例集。先挑阅读影响明确的情境，逐步积累同样合理的替代排法和反例。

验收：每个案例能回答“解决什么阅读问题、依据是什么、为什么另一个方案较差或只是不同”，而非只报告尺寸。未知保留为未知。

### 阶段 B：只读诊断与候选预览

根据阶段 A 规则确定最小数据需求，再封装原生插件读取和副本预览。区分全局样式、有效默认值、局部覆盖、人工定位和渲染几何，正确归一化 mm／sp／内部单位。不得将当前 API 返回的 spatium 数字直接当作毫米。

MCP 的后续接口候选为 get_engraving_state 与 preview_engraving；具体输入输出在数据需求和能力验证后另行定稿。本阶段不开放任意 QML，也不自动写回原谱。预览以明确的已保存版本为基线，不能隐含包括 GUI 未保存修改。

### 阶段 C：局部自动净书

先在副本上比较多个候选，优先修复可明确验证的阅读问题，再逐步加入成组对齐、弧线和连梁建议。评价顺序是语义保护与归属清晰、适用规范、局部可读性、整体一致性和风格偏好。固定权重与阈值必须由案例验证，不能凭空设一套分数就宣布最优。

保留人工锁定和手工偏移。语义不确定、多个方案各有代价或规则未覆盖时报告并交由人工选择。实际写入时才设计作用域、撤销和失败恢复。

### 阶段 D：系统／页面优化与必要本体接口

研究上下文换行、页布局与翻页候选，不机械固定每行小节数。只有插件数据或原生布局控制不足、有复现案例且收益明确时才提出本体改动。不得以本任务名义重写整个引擎或混入演奏编辑器等并发工作。

## 7. 保护、测试与验收

- 原 PDF／MSCZ 使用前后哈希验证；原路径不可作为任何输出路径。所有副本和渲染产物使用独立目录、新文件名，不删除文件。
- 音乐内容采用结构化语义比较；若只做样式试验，同时比较 Style 节点以外的 XML。不能只靠页数或图片像素判断语义相同。
- 当前读取不改变 GUI 选中、撤销栈和保存状态；未实现这些保证前不得宣称已支持当前窗口安全诊断。
- 覆盖线上／线间音、二度和弦、附点、多层连梁、装饰音、多声部、跨谱表、密集变音、叠加弧线／文字、重复音型和系统边界。
- 同版本、同字体环境重复导出；确认没有缺字、回退异常、裁切或新归属歧义。
- 用户实际打印／使用体验另列状态。屏幕结果不能替代已完成打印验收。

### 与字体线的接口

净书线提供实际谱例、阅读需求和验收条件；字体线提供字形、字宽、外框、锚点、建议线宽与版本变化。净书规则不绑定某一个字体名字。对照时分别改变字形和布局，避免无法判断收益来源。字体线独立进度见 [FONT_PLAN.md](FONT_PLAN.md)。
