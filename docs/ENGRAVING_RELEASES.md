## 0.1.0 — 2026-10-23

Git标签：`engraving-v0.1.0`。这是净书线首次单独标记的可用研究版，版本号与MCP运行时版本分别维护。包含此前已形成的知识、案例、原创原生正反例及20个专题入口；本次主要增加进度账本、固定后续清单、发布约定和缓存管理，没有新增官谱阅读成绩。

| 现在可做 | 交付及限制 |
| --- | --- |
| 只读分析钢琴PDF | 指出具体位置、读者任务、保留／改进理由、规范条件和未知；PDF不能独自证明内部voice、播放范围或作者制作过程 |
| 比较已有原生候选 | 区分跟读稳定、占位、归属、层次和行页代价；允许保留默认，不把等距数字当审美结论 |
| 为可编辑输入提出少量副本候选 | 使用本机实际可用的MuseScore原生渲染；由agent核音乐、可见读法和保存重载。缺宿主时仍可分析，候选渲染能力不随skill自动附送 |
| 调用并继续积累知识 | 按问题读专题、实际案例及来源；条件、反例、用户明确偏好和假说分开保存 |

已知边界：Gould和部分外部资料仍未读完；迁移试用1/8类闭合，个人细微审美尚未校准；没有组合完成用户整谱，没有全谱自动净书，没有新增MCP／插件／本体接口。原PDF、MSCZ及教材缓存不随Git标签分发；缺原材料时明确列出，不能声称已看原图。

### 立刻使用

本机尚未发现用户级`piano-engraving`安装目录。可直接把下面这段发给另一个能读项目文件的Codex对话，并替换输入路径：

```text
读取 E:\programming\funcodes\mcp-musescore\skills\piano-engraving\SKILL.md，按其执行。
只读分析 <我的PDF完整路径>，先看整页和相邻上下文。
选出最影响阅读的具体问题，并解释哪些排法应该保留、为什么；不修改原件。
报告所用知识库版本及仍需原生工程或规范核查的未知。
```

希望在其它项目通过`$piano-engraving`选用时，按[一次关联安装](ENGRAVING_SKILL.md#本地发现与维护方式)设置。skill与知识库保留同一checkout；只更新文档／skill时，不需要重新配置MCP。官方支持的发现位置与符号链接说明见[Build skills](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。

若试用发现问题，提供输入路径、页／系统／小节、agent建议和你觉得不对的原因即可；原件继续只读。由本线复核判断并补正例／反例，不把用户变成规范检查员。

## 持续更新与发布约定

正常使用工作分支中的当前知识，新的可靠经验及时进入相关专题，不等待全任务结束。未核猜想写明状态；发现旧错误时标出纠正和影响，避免“最新笔记”悄悄覆盖过去判断。

完成一批综合研读、增加有应用价值的方法，或纠正会改变建议的判断时，发布新的净书标签，记录新增能力、纠错、实际验证和限制。细小修订可用补丁版本；不为每张临时图建发布包。发布时核skill可调用、知识引用可达、原件保护和必要的原生验证，更新进度与剩余范围。

关联安装跟随项目更新，无需每次重装；复制安装才需同步变更文件。标签保留可复现快照；需要并存固定版时使用独立checkout，让skill和知识库来自同一版本。Git中仅保留知识、证据摘要和允许分发的原创样本，私有谱图／书页及整套运行时留在忽略缓存中。
