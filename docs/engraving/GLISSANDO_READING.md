## 1. 为什么端点和线的方向比“斜线整齐”更重要

读者要知道从哪里滑、向哪里滑、覆盖多大音区、何时进入目标音，以及用哪些键。这些任务不同于一条跨表声部引导线，也不同于分句slur。Gould p140建议保留邻近的gliss.说明，特别是钢琴双谱表，避免把动作线误认成声部转移；p326又说明写成普通音阶会暗示逐音指法，不能仅因能生成同一串MIDI就当作相同记法。

| 具体问题 | 处理理由及可用方法 | 不应机械推广 |
| --- | --- | --- |
| 普通确定起止，p141 | 线沿两个音头的音高方向，端点仍容易追到；不越过目标或像从另一个高度开始 | 不是所有线都必须碰到音头；必要空隙、变音、特殊端点和小音有各自条件 |
| 目标有变音，p141 | 缩至变音前或绕其左侧，不能遮住变音。留出识别空间不等于缩短实际音程 | 不为让线“连满”穿过升降号，也不擅自改变目标音／实际键集合 |
| 音程很小，p141 | 可在音符上／下另放短线和gliss.，远离符干；说明动作比硬塞长线更清楚 | 不能为所有短线统一加大音符间距；另放之后仍需明确归属 |
| 跨行或换谱号，p142 | 续段斜率仍须说明真实方向和大致跨度。尽量避免途中换谱号使线的方向与声音相反 | 加线少不是唯一目标；不能只按上下两个墨迹的Y判断实际升降，也不因此全谱删除谱号变化 |
| 不确定或只示范围的端点，p142–144 | 先查作品的特殊头／箭头和演奏说明；线的坡度也不要暗示不可能的音域 | 书中三角头、竖琴箭头等有适用对象；不能把某一种符号当全体钢琴曲通用。内部数字音高也不独自证明精确落键 |
| 滑奏后还有独立发音，p144 | 滑奏的终点与下一次重新弹出的音可能不同，需要各自交代；小头、括号和slur有不同用途 | 不以“最近的下一个普通音”自动接线，也不把所有括起小头当可删提示 |

p144–146还讨论精确中途起滑、长滑音时值及持续声音的记写。它们有助于区分持续／移动和时间范围，但不能无视乐器、复调、踏板或共鸣层，给所有钢琴工程套一个拆值／删tie算法。本轮未重建全部长滑奏、音簇或弦内演奏情境。

## 2. 三个官谱位置分别说明什么

**A010《Again》p3第二系统末与I末：同页有两种斜线。** 前者以叉形起点、波线和gliss.引向低处；I末的斜虚线跨两表，另有手分配括形／提示。第一种描述滑奏，后一种帮助追踪音乐线和交接。把两者全改为实线、或因为斜线穿谱线而删除，会抹掉动作分类。它们同时与普通slur并存，不是都应挤进一个曲线通道。

**A105《Rising Hope》p8 N前：黑键动作由文字明确。** `gliss. on black keys`靠着短上行波线，N另有重音低八度进入。这里并未把普通起止音头逐一写全；不能仅凭最近的N低音、调号或线的几何末端补出一串精确音。紧凑说明让表演者识别一个滑奏动作，代价是不能从PDF还原全部计量／播放对象。页面稍后的叉形起点和gliss.又是另一处动作，不能将前一条黑键文字无条件扩到全页。

**A047《Giorno's Theme》p4 Coda：两条滑奏与音区／导航共同组织。** 两条线分别有特殊端点，其间有谱号变化、8线及r.h.；坡度仍朝上。Coda空白让跳转落点容易找到，也给两条跨域动作留出通道。不能把它们并成一条线、把两个叉头改成普通头，或为节约宽度把Coda塞回前一段；同时也不能只从两条斜线就断言内部轨道和精确手法。

这些是图面事实和阅读理由，不是出版者操作访谈；没有这些官谱工程，也没有声学重建。Gould偏好较轻的直线，而这些官谱多用波线，是规范建议与出版风格选择的区别，不应互相冒充强制要求。

## 3. 用户m113：工程精确，不等于所有图形都在要求精确音高

原PDF p6第一系统有和弦tie、外层slur、发夹、gliss.、叉形终点和S.P.；已保存工程中该滑音的播放方式明确为`whitekeys`，不是从“有一个升号的调”推出来的。线形与播放键集合是两个字段，必须分开保护。

既有原生导出与原工程连接互证：滑音从m113 q=3/2的A4，逻辑连至q=9/4、内部pitch=33的A1叉头；后者跨到Part的下谱表，仍属同一导出voice。S.P.文字挂接在q=9/4，与起始音不是同一时间锚点。**这里的q是对象位置，不是已验证的脚踏物理时间。** 不把S.P.名字已知扩大成捕捉动作已完全确定。

叉头、隐藏附点、无干及特殊滑奏语境提示它不是普通逐音旋律；内部pitch=33同时可供软件连接／播放，但不能单凭这个数字宣布成品要求严格奏出独立A1。反过来，叉头也不是所有作品中的“不确定音高”通用标签。当前保护其形状、内部数据和范围；具体末键精度或是否重新落键，不能由净书程序偷偷改。

起点A4另有tie，周围又有保持和S.P.安排。p146对单条移动音高继续用tie标时长的警告，不足以授权删除这里的和弦保持；仍需区分滑奏动作与留下的共鸣／持续层。本次没有重写手分配、脚法、tie或时值，也没有宣称已证明每个声音的实际演奏方式。

## 4. 本机原生备选：波线改直线，可以减黑，但有真实连动

## 5. 导出揭示的边界：线形和声音不宜被绑成同一个分类

实际MusicXML只有两端标签和line-type变化：原`glissando／wavy`变为`slide／solid`，其它XML保持。当前只读导出源码确实按直／波线选择这两个标签。可是MusicXML一手定义区分[glissando](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/glissando/)的离散中间音与[slide](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/slide/)的连续滑动；两者也各自允许line-type。因此不能从“直线”直接推出钢琴白键滑奏变成连续音高。

本例原生播放与`whitekeys`未改，但交换语义出现风险；不将MusicXML替换源工程，也不承诺其它软件会照原生效果播放。本轮未做导回／第三方测试，不能把这一风险说成已经测出所有软件的错误声音。格式标签和原生私有播放字段是否能完整互换，需独立验证。

## 6. 后续自动净书如何应用

先分类滑奏、声部引导、分句、琶音及其它技术线；再读确定／特殊端点、键集合、计量与开始／结束、层和续接。先提出可解释的归属／遮挡疑点，再决定线形、线宽、文本及避让，不以线的数量或统一坡度打分。

原生已分别有线形、播放方式、播放开关和端点等控制，不需为了分析先加MCP。以后做适配，应先可靠读取／保护这些现有信息，检查实际图面；短线显示设置存在也不保证文字最终能画下，当前源码有长度不足就不画文本的分支，实际情境需渲染核查。发现交换分类问题先保存本例复现；可评估导出后处理或必要的最小本体修正，但单改标签仍不能自动保全白／黑键、时间等全部私有含义。本轮只形成依据，不实现这些方案。
