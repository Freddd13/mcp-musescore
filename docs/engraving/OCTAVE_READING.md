## 1. 为什么有时保留加线，有时换八度记法

八度记法减少连续加线，却要求读者持续记住另一个音区。频繁切换会掩盖实际音程与手的位置。因此Gould p32–34、324建议把偶发的极端音／和弦优先写足音高，让跳跃可见；较长高／低音区可用八度线，并尽量保持整个音型在同一转置中。书中的三／四条加线是读谱情境中的建议，不是所有乐器、织体和字距的硬阈值。

**A009《Adabana Necromancy》p1–2可同时看到这两种选择。** 高处厚和弦保留加线，邻近连续小组才用短8va；小组结束的角明确，后面的低位置材料不用一直维持转置状态。好处是高和弦的实际距离仍可辨，运行不被密集加线盖住；代价是要多次重新确认音区。不能只统计八度线数量或加线数量，判哪版更好。跨页续接的另一个已核例是本谱p3–4，见[分行与翻页](PAGE_FLOW_STUDY.md)；本轮新复看的是p1–2，不把它们误称跨页续线例。

**A146《Zen Zen Zense》p8把局部恢复也写出来。** 第二系统末下表的短低八度区后有loco，附近又换谱号；后续上下表的8各自限定材料。它要求读者重新确认当前音区，不能因为都在同一大括号内，把一条八度线解释成整个钢琴的状态。本页也有用8罩长和弦的出版选择；不凭“官谱这样写”或“书中偏好加线”直接改写，须连音程轮廓、前后进入及竖向空间比较。本轮无其工程，未反推voice或逐音演奏范围。

## 2. 线的位置在帮助读者记住什么

| 情境 | 阅读理由及处理条件 |
| --- | --- |
| 起点邻近变音 | p28允许以最左变音处或音头附近安排8，紧时可正对音；字样左边界不是独立的时间轴 |
| 长范围与短变化标记并存 | p29按持续范围安排层次；整行八度状态建立后，较频繁变化的信息靠近音符更容易读，速度／踏板等另有位置条件。不是八度线永远最外、所有标记同高 |
| 跨行／跨页 | p30在上一系统延到行末，下一系统重提示8或括起8；这仍可是一条逻辑范围，不因看到两个8就合并／去重或重奏 |
| 普通长音结尾 | p30通常在线尾角越过最后音头及其附点处结束，不必拖到该音书写时长的右边界；八度线不表示放开琴键的时间 |
| 颤音、重复小节、省写反复 | 同页及p31给出需沿持续范围或仅罩写出材料等不同例外；不能把“收在头后”机械套给所有线 |
| 短休止／长空段 | p31可跨短休止保持状态，较长休止可分开提示；先认是否仍有连续材料，而不是按每个休止自动截线 |
| 远离音头或只作用单音 | 角、竖向虚引导等可帮助限定；不能把远处一条线的横向投影当作全部归属证据 |

p324–325进一步要求钢琴分清作用谱表：共梁不自动让一条八度线涵盖两手；一表同时有转置与loco材料时，要有明确区分，必要时多一表反而更清楚。8va移八度与col 8（加写八度的省写）也不是同一动作。改变谱号、重写八度或范围属于记法选择，不能夹进纯间距整理。

## 3. 用户工程的实际问题：范围还在，空表便被保留

原MSCZ中，原生staff 6的8vb从m148 q0指向m153 q0。m148、149各有两个背景音，以tie相接；中间被多罩的m150–152没有该表的Chord，只是休止。旧文件还保存了起段与末段两个手工Segment。

同哈希冻结宿主的本轮新基线，与上一轮八页SVG对象几何一致。其尾页在O之后留下这个空低音表，印出休止、低八度续线、大括号和穿过题献的小节线。不能先把它当成行距参数差，或只隐藏看得见的休止：仍在活动的范围也可能影响空表保留。当前证据说明此输入与宿主的连带行为，没有证明所有空表都该删，也没有确定这是本体缺陷还是不同保存／输出状态造成。

### 两步候选及拒绝理由

| 副本 | 实际改变 | 结果与判断 |

这是**记法范围收束加局部几何整理**，不是只拖一条线。范围改变经过确认：被收掉的区间没有该表的既存音符；没有改五个背景音、tie、延长、其它谱表或全曲音高。MusicXML把旧stop写在m152 q3，新stop写在m149 q4，分别等价于原生m153 q0／m150 q0；跨格式应比较实际边界，不能只比较小节标签。

原生保存重载后，范围与末角保持；八页绘图对象／像素与最终候选相同。其余七页与新基线的绘图对象集合、180dpi合白像素相同；尾页仍为三系统，其中活动／背景四表保留，仅后面不需要的空低音表及相关图元退出，O的局部排版随之改变。3203条MusicXML音／休止记录在排除位置和Bézier几何后相同，完整MIDI也相同。没有把MusicXML重新导入测试，也未做实际打印／试听。

## 4. 为什么完整MIDI相同仍需检查覆盖了谁

本文件Part 1、2的Channel保存`solo=1`，Part 3未solo。原基线MIDI只有track 1／3／4的NoteOn，m148的五个背景起音没有出现；因此“完整MIDI相同”本来没有直接验证这些背景音的发声。

本轮另做两份**仅用于诊断**的副本：分别从原基线及最终重载版让Part 3也solo，再导MIDI。两份均出现track 5的三个音、track 6的两个音，NoteOn从2310增至2315；两份完整文件逐字节相同。最终候选仍保持原来的solo配置，诊断版不作为净书方案。这个对照支持当前背景音的音高／演奏事件保持，不证明S.P.的物理脚法或CC66已实现；本轮也没有试听。

一个具体音区核查说明了字段含义的重要性：上方终音原生pitch字段93，在MusicXML及原MIDI为105；下方两个原生字段45／61，在MusicXML及诊断MIDI为33／49。[MusicXML官方定义](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/octave-shift/)的方向是从演奏值移到记谱位置，所以谱面8va在XML中可为down，不能按名称反向再转一次。本例的差12符合八度上下文；并不证明所有插件字段都返回同一层音高，实际接口仍须核定义。

## 5. 几何差异也要先分清，避免制造假问题

初比SVG字符串时，第2／4／7页不相同；实际只是对象次序不同，带变换的绘图对象集合及合白像素均相同。不能将它写成其它页重新排坏。MusicXML最初有六条note记录不等，差异是Bézier位置，排除布局后记法／事件相同；也不能凭note XML字节不同就改音。

原生SVG的Note路径还使用局部坐标加matrix变换，八度线多为页坐标。先把字形控制点变换到共同坐标，才能比较线角与音头；本例使用控制点包络作保守包含核查，再实际看图，不把包络当通用墨迹框或美观评分。见[输出阅读](OUTPUT_READING.md)。

## 6. 这轮怎样积累成可用判断

以后遇长八度线／空表，先查作用谱表、实际目标音、前后边界和续段，再看几何与留白；改变范围后重查旧手工偏移是否仍合用。遇音高差12先查八度上下文和字段层次，不擅自“校正”；遇MIDI保护先确认播放覆盖了哪些Part／声部，静音／solo下的缺席不能代替语义检查。
