## 1. “按规则知道这个音”与“眼睛能立即确认”是两件事

通常的小节内变音规则让记谱不必每个音都重复符号，但读者会受到刚弹过的音、换行、换谱号和跳回位置影响。提示变音为这些记忆负担付出一点空间；必要变音则直接决定怎样读音。两者都不能按“多一个符号就不美观”去删，也不能只从工程的USER／AUTO角色判断人类是否需要它。

Gould p80–83给出一组相互制约的条件：

- 跨小节tie只延续被连住的发音，不自动为新小节后面重新奏出的同音建立整小节变音状态。后一个音需要明确确认；不能因为前一个同音显示为升号就去重。
- 同一行内紧接的tie接收音通常无需再印；反复在每条小节线后给tie补变音，可能让长持续看起来像要重新起音。
- 新行开始的tie提示可减少回看。若用普通未括起变音确认，后面近处同音可能不再需要重复一次；若整串密集和弦都补，行首又会拥挤。它是按音乐密度和辨认任务选择，不是每条tie统一加或统一不加。
- 小节线已经重置普通变音作用，但紧接的再现仍可能让人怀疑漏印；调号已能纠正也不等于演奏者不会迟疑。长半音小节、不同八度间的来回、装饰音／装饰记号还会产生其它确认需要，不能只用“上一音是不是同MIDI音高”处理。
- 圆括号能说明提示身份，也增加宽度和字形辨认成本；少量有用，不宜给密集提示全部套括号。方括号又可能表示编辑增补，不能按造型喜好互换。

因此诊断应先说“读者可能把它记成什么、为什么”，再说是否值得提示，以及提示放在哪里。提示不足不等于源音高错误；外观候选也不授权改实际音高、tuning或拼写。

## 2. 官谱怎样选择提示，而不是把所有地方都写满

**A008《A Link to the Past Medley》PDF p9，V／W首小节的低谱表。** 三降号调号下，重复和弦先有普通还原，稍后相同音区再用括号确认；并非每次和弦都重复。读者跟着上方另一层和下方连续音型时，局部确认减少回找前面还原号的需要。括号因此有明确阅读用途，同时占据实际宽度；不能先删括号缩紧，再把变窄当成成功。本轮只确认可见的前后关系，未获得工程或逐个证明全页其它变音的必要性。

**A005《200 Anime Songs Medley》PDF p6，G的两个结尾。** 共同段进入第一结尾后回G，再次经过共同段时跳到第二结尾，随后才进入后文；不是把版面上相邻的两个结尾连续演奏。两结尾有相似音型、变音与持续，末尾时值／走向又有差别。应分别从各自实际来路读起，不能沿纸面顺序认为“第一结尾已经交代过，第二结尾重复符号可删”。这里只做可见路线与记法分析，没有全曲逐音、持键或播放核查。

G起点在行首，第一／第二结尾留在同一行，结尾数字和括号仍容易归属。后者无需为“第二结尾必须行首”再拆。G后转H的四升号在前系统预告，下一系统重新出现；这两个位置分别帮助准备和恢复状态，不是简单重复对象。

**A047《Giorno's Theme》PDF p1–5，Segno／To Coda／D.S.。** 具体位置为p1第三系统行中A的Segno，p2第四系统末To Coda，p4第五系统左段末D.S.，其右侧隔开的双谱表片段为Coda，G从下面新系统继续。结合这些标识，本线读取的路线是：首次经过p2继续向后；到p4 D.S.回p1 A；返回经过p2 To Coda时跳至p4小片段，再接G后文。这是静态标识的路线解释，不是宿主播放结果。

这例补充了[行页研究](PAGE_FLOW_STUDY.md)的导航条件：回头跳跨了几页，读者需要很快认出目标和恢复音区／力度等状态。D.S.前已有mf，与首次到A前的mf相呼应，不能只因A旁未重新印一个mf就判漏记；出发前的上八度线已经结束，Coda内另有局部八度和换谱号，也不能把之前的音区范围越过跳转点延长。小片段重述谱号、调号和大括号，让它作为跳转落点独立可读；抹平空白并省掉这些“重复”会削弱找路。没有据PDF反推内部voice、精确对象或编辑者实际决策。

## 3. 换调、换谱号和反复线的顺序在说明什么

Gould p92–93同时列传统与当代的调号取消方式。传统做法可在新调号前列还原；当代做法通常只印新调号，转为无调号时仍须明确取消。这些是不同出版惯例，不能把“还原较多”或“没取消全部旧符号”单独当错误；先确认新状态清楚且上下文一致。换调也未必就是新结构段落，不应见到调号变化就机械加双小节线。

调号变化碰到行末时，前行预告与新行正式调号各有任务；两者的取消符号不必完全复制。换谱号和调号同时发生时，p93先放小节线前的谱号，再在其后的新谱号语境中放调号，读者才知道各升降落在哪些音位。本轮没有用当前宿主逐项重建这些排列，不能由教材直接报软件缺陷。

p234–235把这件事推进到实际路线：反复段开头的新谱号／调号／拍号先交代，再放反复起点；中途改变过状态时，要清楚说明回来后读哪一种。第一结尾为了返回而恢复的状态，与第二结尾应继续的状态可能不同；只影响反复以后音乐的变化，又应放在反复线之后。不能只依据横向坐标把这些符号挪到同一侧。

力度也要区分身份：返回点括起的(f)可以是提醒，`2nd time: …`则可能是第二遍不同演奏的指令。去掉括号或合并文字可能改变读法，不是纯字体清理。首／末结尾括号开闭、跨行续段和编号还承担路线提示；常见最后结尾的开尾不能按“有线缺口”自动补闭。具体例外及排练编号见p236–237，本轮未据此完成所有多次反复、嵌套或重复小节号的实现核查。

## 4. 原创六小节：同样的音高，符号的位置改变了读法

本次一个有用的实际结果：m4第一音加未括起升号后，当前宿主自动不再打印该小节末拍的升号；m2额外重复版也发生对应变化。不是把后面的音改成自然音，MusicXML中`alter=1`仍在。于是“音符没变”与“其它可见符号完全没变”要分开，不能做完提示就不读回，也不能用变音符号总数判断是否更好。

选择版保留了m2必要的再起音确认，且只在明确的行界／回跳情境增加提示；本线认为比对所有tie统一补符号更有理由。它仍不是用户选择、密集实曲改好或已测读谱速度的证据。m5括号提示增加实际占宽、让末系统变长，若放入密集实谱，还需重新衡量这个成本。

## 5. 后续应用：先走实际路线，再评价符号和空间

遇到提示或导航问题，先建立写出的小节位置与实际经过顺序：这次从哪里来，是首次、返回还是跳过第一结尾？分别确认目标处的谱号、调号、拍号、八度范围、力度和持续。与源音高／拼写核对，分清真正读音错误、必要确认、减少回看的提醒和出版习惯；未知状态只提出疑点。

再找阅读成本：是刚才同名音仍留在记忆、离原提示太远、换行不便回看，还是Coda难定位？只对有理由的位置给少量编辑建议，保留已有效的提示和手工覆盖。提示策略确定后，再调符号列与整行间距；不能为美化删掉提示，或先为全谱加满再压紧。

对未来Muse适配的具体要求是：能够区分音高数据、可见变音、AUTO／USER来源、括号身份，以及tie／小节线／实际来路；候选后读回自动显示的连带变化和页界。仅按线性前一小节或当前voice推导，不足以处理独奏钢琴和反复。当前只是从这些实测形成需求，未实现诊断器、演奏路线展开或接口。
