# 弧线的假断口：先核裁图、矢量与输出管线

2026-10-20，承接[弧线专题](CURVES_STUDY.md)与[输入历史](INPUT_HISTORY.md)。本轮从用户p6弧尾看似灰淡／断开出发，最后**没有证实需要补接、重置或加粗的断弧**。复看用户PDF p5–7、A062《Idol》p1–2及Gould p65、109、111–113完整图页，均为已有材料续核，不增加历史覆盖计数。[证据](output_reading_evidence.json)保留初始怀疑、矢量／像素核查及保留判断；不把这个局部结果推广到全谱所有弧。

## 1. 开放续接、平缓中段和真的断裂不是同一件事

Gould p109允许长slur的中部压平以靠近谱面；p112要求跨行段看起来仍待续接，单音接收处尤其需要辨别方向。tie的跨行形状另有p65的对称要求。不能把每个开放尾都画圆收回、补到最近头，或把每行片段当新句。

A062 p1末音上方的开放slur接p2 B附近的接收和弦，邻近有奏法点及和弦tie；页内又有较短的局部弧。只裁那颗音，短尾可能像一条独立tie；结合上一页和奏法才能保住重奏／分组的不同。两类线在层次上分开，比让所有曲线同样圆、同样长更重要。本轮无其工程，不反推具体spanner容器或作者手调步骤。

用户p6的长弧也须看整个系统及邻行。初次紧裁图分别从约372／372.5pt开始，裁掉弧顶，甚至漏掉整条较高的弧；不能把这种预览交给自动诊断去补接。换用180dpi、包含上方空间的完整系统区域后，可以看到完整拱形。裁图应覆盖实际曲线及接续上下文，不只围住符头带。

## 2. “看起来更淡”不等于工程线宽变了

原PDF元数据为MuseScore 3.6.2，当前MSCZ记录3.6.3。m117、119、121的选定Slur起点没有保存手工SlurSegment；其它位置有手调，不能称整曲没有。版本字符串、缺手调字段和屏幕观感，都不足以分别证明用户调坏或兼容缺陷。

进一步核对一个完整弧段：

| 证据 | 实际结果与能说明什么 |
| --- | --- |
| 原PDF描边 | 约0.089008pt；不是从截图估算 |
| 当前原生SVG | stroke-width=0.45，按该SVG的实际viewBox／物理页宽换算约0.090pt；小差别在输出舍入量级 |
| 同私有基线新导出的原生PDF | 仍约0.089008pt；选定曲线全部控制点与SVG换算后最大残差约0.00068pt |
| 同一当前几何的180dpi预览 | Qt PNG与新PDF经PDFium渲染，局部深浅仍不同；所取纯弧ROI的等效黑像素约1.72／2.53每列 |

该ROI统计是把灰度转为覆盖量后按列求和，**不是美观分数、实际线宽或全曲黑度**。同一路径经不同输出／栅格化管线，能产生明显观感差别；本轮未证明具体由哪一种描边调整、抗锯齿或其它内部算法造成，不给渲染器报一个未经定位的bug。

因此，“PDF较黑→旧Slur更粗”“PNG端部淡→当前曲线被剪断”“换版本／字体造成全部差距”在本例都没有证据。当前工程重新导出PDF后，该处弧仍完整、清楚；不应为了让PNG像另一张PDF截图而增加线宽。出版目标的判断应尽量比较同格式、同物理尺寸及同渲染路径，同时用矢量解释几何。也不能据此否认真实的间距、线重或归属问题，后者仍需各自证据。

## 3. PDF提取的外框也不一定包住曲线

本机pdfplumber给原PDF这一条拱弧的`height`返回0，`top`／`bottom`同值；但完整路径有两段cubic。由每段Bézier曲线的导数求内部极值，再联合端点，实际**填充路径高度约9.524pt**，还未计描边外扩。不能把返回的0当作没有墨迹，也不能仅按这个框选区／裁图／判碰撞。

这是一条真实工具输出的反例，不是所有PDF外框都不可信。符头字符框、绘制原点、曲线控制点框、曲线真实极值框和描边墨迹框分别是什么，必须先弄清；控制点本身也不一定落在曲线上。原生SVG用于几何时同样应按其单位与路径计算，不能把坐标数字直接当pt。

## 4. 本轮的处理与后续用途

结果是保留用户当前连接、曲线与样式；没有生成新的线宽／几何候选，也没有重跑旧MIDI测试来冒充本轮成果。唯一新原生导出是从已核哈希的私有完整基线生成8页PDF，原PDF／MSCZ均未写入；字体、GUI、软件适配及实际打印／试听都未改变或执行。

以后遇到“线太淡、像断了”的诊断，先扩大上下文、核跨行角色及矢量连续性，再比较相同输出管线。若证实实际路径／墨迹不同，才定位连接、控制点、有效样式和避让；若只是预览差异，不对工程作补偿性改写。不要求每个简单分析都导出全部格式；本例因初始图面疑点与矢量证据冲突，才补这一项控制。
