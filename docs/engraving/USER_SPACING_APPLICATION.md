# 将间距判断用于《如果有来生》副本

2026-10-19。接续[原创候选与迁移反例](SPACING_CANDIDATES.md)，这次使用用户实际工程的独立副本，研究第2页第4系统m49–52；原PDF和MSCZ只读，没有改插件、MCP、本体或当前GUI乐谱。测量及保护范围见[user_spacing_evidence.json](user_spacing_evidence.json)。这是一个真实片段的可行性研究，尚非用户认可的净书成品。

## 先判断读者在跟什么

m50–52的下谱表同时有连续八分音符与持续的附点四分低音。八分层是可跟读的重复动作；上谱表则从四分／八分进入m51后半的十六分，再回到m52的较厚和弦。应同时保护三件事：下部连续动作容易认、上部细分组容易读、真正同时的起音有共同时间轴。

这里至少有两类不同的疏密：m50和m52各自内部很均匀，但前者整体步长更大；m51内部则前三个距离约15.68 pt、后两个约19.60 pt。不能用一句“左手不均匀”把两种机制合在一起，也不能只独立拖左手音头。

m51没有印出的临时变音，不能把这个约25%的差异归咎于变音列。另一手增加细分与原生时间列弹性是已有自制探针支持的解释；实际各列还受符干、旗尾、加线、弧线和行宽分配约束。m50／m52整小节粒度差的唯一成因尚未完全隔离；能用stretch调整不等于已证明原始差异全部由某一默认值造成。

## 为什么值得试，为什么也可以保留

Gould印刷p39–43及p490支持同时考虑同类时值的稳定、每拍最复杂一部的需求和真实符号净空，详见[间距取舍](SPACING_DECISIONS.md)。官谱A102也会为上部复杂细分让出空间，并非伴奏全程严格等距。因而本例的任务是检验能否减轻**无必要的**失衡，不是消灭所有不同步长。

原排法没有因此变成错误记谱。拍组、梁和两部对齐已经提供节奏线索；对熟悉音乐的读者，毫米差别未必形成阅读障碍。用户对之前极简6/8两图反馈“暂时看不出差别”，尤其提醒我们：方差变小只能证明几何变化，不能代替感知收益。该反馈只针对自制例，未表达对以下实曲候选的选择。

## 三个版本，各自回答一个问题

保持同一宿主、字体输入、样式、纸幅、原有音乐和换行；没有重分voice、改音高／时值或给音头加offset。原工程未显式保存Music/Text字体家族名，因此这里固定原输入与同一宿主，不伪称文件显式选择了某字体。三版均为8页，m49–52仍在同一系统。

以下均为下谱表连续八分音符相邻**符头绘制原点**的距离，单位pt，适用本例正常侧音头；不是一般二度和弦外框中心测量法。

A只给m50、m52设置小节stretch 0.93、1.07。B在A基础上给m51 stretch 0.5，并在其下谱表第2、3、4个八分和弦后的共同Segment节点设置leadingSpace 1.40、2.30、1.95 sp。索引为原生顶层Staff 4的voice容器0；小节stretch序列化在Staff 1对应Measure。不是把这些数值相加到某个音头最终X；它们影响最小宽度，再参与整行分配，机制见[原生属性研究](SPACING_CANDIDATES.md)。这组数值仅供复现本片段。

A有意把m50稍压、m52稍放，代价是小节线与m49的分配也轻微变化。B又把m51较短的前部距离放开、后部距离收回；上部十六分的相对位置、连梁走势及弧线随之重算。B同时使用局部最小宽和小节弹性，不能把它当作单参数因果实验。两版都需看完整上、下部，不能仅按下部距离给分。

## 不采用的尝试教会了什么

- 只把m50／52 stretch改到0.85／1.15会把疏密差反向放大，不能无限增加补偿。
- 复制自制谱附近的leadingSpace数值，实曲m51曾得到20.468 / 16.468 / 13.884 / 17.356 / 17.800 pt，比原来更失衡。每列已有最小宽不同，不能把同一个“补偿量”到处用。
- 把三个局部最小宽均加到3 sp，会使目标行由4小节变3小节。单个脉冲更宽可能以系统重排为代价；必须检查全页，而不能只量一个组。

因此后续可以研究“根据当前列宽提出候选”，不能从本例直接生成全谱样式预设。若未来要优化引擎，目标应是共同时间轴上的脉冲稳定、复杂层净空与系统预算之间的取舍；是否需要本体改动仍须更多失败例。现有原生属性能做出本例候选，不等于插件/MCP已能安全完成相同工作流。

## 音乐与连带效果的核查

副本输入的原生XML除列出的Segment／stretch节点外完全一致，ZIP其它条目内容一致。整谱原生导出MusicXML，去除列明的布局坐标、print、measure width和wedge spread后，三版结构与内容一致。此检查保留音乐offset、连接、文本及其它非布局内容；MusicXML并不表达MuseScore所有特性，因此原生XML比较仍是必要的一层。

m50–52每小节4个上、下部共同音符起点，三版各12个均保持同X；此核查只覆盖所述voice正常侧音头，不外推到休止的光学偏移或其它片段。两候选的第1、3–8页SVG几何和文字与基线相同（忽略文件标题）；B经原生保存、重载后8页SVG几何与PNG像素均相同。

第2页并非只有目标行改变：第2、3系统整体有微小纵向位移，目标第4系统上、下谱表间距也略变，最大谱表顶线位移为A 0.216 pt、B 0.218 pt，约0.08 mm。原工程开启vertical spread；局部形状改变后重新分配页面空间是与现象一致的解释，但未唯一定位触发对象。**像素差异外接框覆盖多行，不代表各行发生大幅移动。**

已看三版第2页完整原生图和完整m49–52上下部裁图，未见明显新增碰撞、缺字或裁切；没有宣称自动碰撞穷尽检查、实际尺寸打印或演奏更易读。原MSCZ前后SHA256相同；本次没有把原PDF重新导出或写回。

### 先看具体构型，再解释“同样节奏为什么不同宽”

m50上谱表第二个Chord是自动上干的孤立八分，m52对应八分和弦为下干。下谱表两处的音区也不同，加线分布随之改变。m50下谱表第四个八分G4还附两个括号Symbol，并设`play=0`；同一时点上谱表和弦包含G4。保留伴奏轮廓、提示另一层发声是与这些事实相符的用途解释，未代替用户确认手分配。它既不能按可见头数当作额外起音，也不能因不播放就删除。

Gould p41要求兼顾干向造成的视觉成团／分散，p43说明符号负担与节奏间距需要取舍；这并没有提供本例差异的唯一数值答案。复看A102 p7也看到复杂运行与三连伴奏共用空间，见[官谱的具体时点分析](SPACING_DECISIONS.md)。出版观感来自可预测的组形与必要净空共同成立，不能由“都写八分”推出每个小节必须占同宽。

下面的改干向、隐藏／移除括号、加线长度置零，**全部是诊断控制，不是推荐排法**。每个都从原私有副本独立建立；加线置零还会影响全曲，不能冒充局部优化。表中为m50／52下谱表六个八分的五段平均头原点距离，单位pt；这两处正常头可用该量，不是二度外框中心的通用规则。

### 一个局部构型为什么连未改的小节也会变

只改m50一个八分的干向时，MusicXML实际布局宽度由237.41降至232.96 tenths；同系统m49、51、52却各增加约1.48 tenths，四小节总宽保持。不是独立把m50的某个音头往左拖了一点，而是它改变了需求后，固定整行重新分配空间。

当前只读源码`Measure::layoutWeight`对普通小节取持续长度，`basicStretch`结合用户stretch与measureSpacing；`layoutSystem`再按该权重分配余宽，随后伸展小节。相同长度的本行各小节原来使用相同基本stretch，这能解释观察到的近似等量连带；当前源码提交与固定二进制构建对应仍未证实，不能用静态公式替代本次实际输出。

这与m51组内`2/1.6≈1.25`是不同层次：一个是小节获得多少空间，一个是内部联合时间列怎样分；局部形状还会改变两者的约束。改全局松紧、强行翻干或删提示，不能代替先认清是哪种问题。

### 当前怎样处理，而不是把控制变成预设

本集合中，A才是在保留原记法的前提下专门平衡两小节粒度的候选：只重建m50／52的stretch 0.93／1.07，全部干向、加线样式、括号、静音G4、音符与标记都保留。m51仍有约25%的内部差异，A不冒称解决它；此前B是另一个联合候选，不能挪用其保存重载结论。

本批A与基线同为8页、38系统，m49–52仍同一系统；12个共同音符起点保持对齐，其它7页SVG除文件标题相同。m50下谱表上方同Y相邻加线的最小端点间隔，从7.39pt变为6.48pt，仍分开；这只是7对水平线的限定检查，不是所有墨迹的自动碰撞验收。整页与整行实际看过，未见明显新增遮挡。全部11个输入的非目标原生结构（包括富文本尾空白）、ZIP其它条目、MusicXML音符事件与完整MIDI保持；MIDI确有2310个起音，未以空文件比较代替。

本轮没有新增保存重载、MusicXML重导入、打印、试奏或用户选择。当前保留原工程；若后续要采用A，理由是相邻重复伴奏的粒度更接近，代价是m50稍紧、m52稍松及全行轻微重排，仍须看实际阅读收益。不能把0.14%当用户偏好或出版质量评分。[Kokecola的实践](https://note.com/kokecola/n/n6df2c29e9942)也把落点放在演奏者能顺畅读取，具体细则并未在文章中全部展开；此处不从文章拟合本机参数。

后续软件研究更有价值的目标是：让每个必要构型的最低净空可被解释，同时在整行中控制重复参照层的粒度波动。这个实例提供干／旗、加线和无效删括号的具体复现，尚未证明需要某个全局补偿常数或本体修改。本次没有开发适配。私有输出在`tmp/engraving/system-spacing-2026-10-20/native/`，`baseline-focus.png`与`grain-candidate-preserved-focus.png`为同框完整两手对照，均非公开素材。
