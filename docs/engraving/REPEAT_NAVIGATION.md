## 1. 先分清重复了什么、从哪里重新进入

| 情境 | 阅读理由、依据与边界 |
| --- | --- |
| 连续短型完全相同 | p230建议省写适合易记材料和较长重复；孤立一次省写反会打断眼睛的连续跟随。复杂织体还要追同步，不以少符号为唯一目标；拍重复斜线的体裁条件也不能推广成通用钢琴记法 |
| 单小节重复符号 | p231–232要求内容相同；起始接有tie／slur、整串长音tie、换拍或前一小节是休止等情境不能机械替换。新系统重写材料能避免回看前行。重复材料中的动态是否每次生效，也须读清楚 |
| 两小节重复 | p232–233要求可独立辨认的组，首述两小节不拆行；不能把两个相同单小节重复或含整休止的组随便合成双小节符号。省写的代价是需要可靠的回看位置 |
| 第一／第二结尾 | p234–237要求按每遍的实际进入状态读谱号、调号、拍号、提示变音及动态。末次结尾之后会继续的内容，不是第一次结尾的线性后继；即使只差一个延长，也可能需要分别交代 |
| 结尾括号跨行／开尾 | p237的跨行首段可开尾，最后结尾通常只罩一小节或两个短小节并开尾；曲终、重复小节号等有另外条件。不能因一边没有钩就补闭，也不能把括号长度当作全部持续范围 |
| D.C.／D.S.及Fine | p238–240区分返回曲首／Segno、读到Fine停止、到指定出口再去Coda；纸面最后一小节未必是真正结尾。小节号通常连续编号，不把每次经过都当新写出的小节 |

p229另提供一个与[持续弧案例](SUSTAIN_AND_RESTS.md)相通的提醒：双音震音跨多个值时，书中用整组slur避免逐对tie造成复杂，也表达避免重新强调的持续关系。它不是将所有slur都改判为持音；对象名、图形与实际功能仍须结合本处意图。

## 2. 官谱怎样让跳转落点容易找到

**A016《Avid》p3，第五系统的D.S.与行内Coda。** 左侧音乐到D.S.结束，右边先断开谱线，再重列大括号、两谱号与调号，Coda符号位于新片段上方；随后G在下一系统继续。短断口让右段有独立入口，又能利用同一行剩余宽度。若抹掉断口，只剩普通小节线，读者可能先把它当成D.S.之后的顺序小节；若强制另行，又要消耗一行高度并重分后续预算。本页仅据可见落点作判断，没有在此复演整首返回路线。

**A028《Catch the Moment》p4，末两系统。** D.S. al Coda在上一系统末，下一系统以Coda符号及文字开始，I在同一行中部再出现。Coda落点和后续主题进入不是同一位置，因此没有理由把I拖到行首或把Coda并到I。新系统没有明显内缩，仍可借清楚标识找到；Gould p239推荐新行Coda内缩，这是可以比较的帮助，不等于所有未内缩官谱都是错误。

**A084《Little Busters!》p4，第二→第三系统。** D.S. al Coda在下方行末；H与Coda从下行起，附近还有8va、上部p／sfz和sempre legato、低部mf等不同说明。这里需要同时恢复路线、音区与各层演奏任务。不能只保留最大的H，删掉“重复”的Coda／八度标识；也不能为留更多空白把这些不同指令合成一个远离音符的标题。

A016／A028的D.S.在上方，A084在下方。Gould p240对大谱表更建议下方显著安排，官谱实践并不统一。当前应判断字样是否容易找、属于哪个边界、与音乐说明是否分清，不把书中一种位置建议直接升级为全目录批量移动命令。这些阅读收益是本线的解释，不冒充出版者亲述。

**A005《200 Anime Songs Medley》p6，G的两个结尾。** 两个结尾在同一系统内，首个封口，末个开尾；共同段和结尾之间还有tie关系。第二遍从共同段进入第二结尾，不经过第一结尾：不能按左边刚出现的音／变音状态替代第二结尾的必要确认，也不能把tie到两个不同结尾的作用压成一条线。这里不要求第二结尾另起行，因为两个数字及范围已清楚，另行会增加回找和空间成本。完整实际来路分析承接[提示变音](ACCIDENTAL_CONTEXT.md)。

## 3. 教材的布局建议怎样有条件地使用

Gould p239建议Coda显著可寻：新行可内缩，行中可留出谱线断口；断口后恢复谱号／调号与大括号，使它成为可独立进入的片段。p240还建议返回／跳过的段落尽量从新系统起、Fine尽量落在行末。它们服务于定位，不是要求固定四小节一行或所有结构标记都独占一行。

应先走每种实际路线，问进入处必须知道什么：当前音区、速度／力度、踏板／持续是否延续，哪些状态需要恢复或提醒。目标处缺少一个标记，不能只用纸面上一小节的内容“补全”；反过来，首次进入已清楚且返回前已恢复的状态，也不必盲目重复一整套。

若跳转跨页使演奏者不断回找，p239也提出写出部分或全部重复材料的选择。增加页数可能换来更可靠的路线，但需重新评价翻页、编辑范围和全曲预算；不能在纯外观清理里擅自展开、删除或重排音乐。

## 5. 同图异路线：漂亮或音数相同都不足以放行

[拒绝控制MSCX](fixtures/navigation-rejected-wrong-return.mscx)只把另起系统版的内部`jumpTo`从`segno`改成`start`，显示文字仍是D.S. al Coda。完整SVG与整页合白像素完全相同，50个写出音的MusicXML记录也相同；实际MIDI却走`1–8 → 1–5 → 9–10`，75次NoteOn，错误多奏引子。MusicXML也将该控制由`dalsegno=segno`导为`dacapo=yes`，可见文字没有自动纠正。

这是**有意制造的错误控制**，不是发现MuseScore会自行改坏跳转。它证实了核查范围：不能只比截图、写出音数、源音符清单或某次播放事件总数；需要核可见指令、内部目标／出口／续接与实际展开顺序。若没有音乐数据或没有测试，就明确保留路线尚未验证的状态。

几何统计也有一处具体反例：行内框让StaffLines绘图对象从20变70，却仍只有两系统，部分谱线改为分段绘制。不能把线对象数除以10当作双谱表系统数；本例用实际图及MusicXML的print边界确认，而非制造“多出五行”的假回归。
