# 持音的续行提示：提醒原音，还是要求新的动作

2026-10-20。承接作者已确认的[持续与休止案例](SUSTAIN_AND_RESTS.md)，完整复看Gould印刷p72–73、336–338／PDF p92–93、356–358，复看A021 p4、A056 p8、A059 p5及用户p7；本轮均为复读，不增加历史覆盖计数。只读用户原件，另作原创CC0八小节原生对照及实际MusicXML往返，见[证据](sustain_continuation_evidence.json)。

**本轮判断：持音提示首先交代动作和状态，不能仅以少画几条弧为目标。** 括起的持音、完整tie、无声按键和新的普通音头，有时都不会在软件中立即发声，却可能要求完全不同的演奏动作。跨行提示还须区分持续的中途与结束边界。

## 1. 四种动作为什么需要不同线索

| 情况 | 读者需要知道什么；依据与例外 |
| --- | --- |
| 手指继续持键 | 手仍被占用，写足保持长度；Gould p337。不能把长音缩成短音，再由软件“不重奏”替代手的动作说明 |
| 已由选择延音踏板保持、手已离键 | p337允许用便利的书面长度，并用踏板范围交代留声。新系统或必要处可用括起音高提醒哪些音仍在；括号同时说明手已从这些键释放，不能只理解成装饰字体 |
| 无声按下琴键以产生共鸣 | p338以菱形头交代特殊动作，手仍要按键并保持相应时长。它与“先奏过、已由中踏板接住”的提示不同；两者都可能没有新的NoteOn，不能据此互换字形 |
| 再次奏出同音 | 普通音头通常是新起音；即使同一踏板仍保持旧音，也可能有意重奏。必须看本处意图，不能按同音／不播放属性去重或将普通音头默认为持续提示 |

p72的一般开放tie与p337的钢琴条件须合读：短开放弧可说明超出书面时值的余响，长弧到休止／小节线又可交代保持范围；钢琴有踏板控制时不必把每个延续值都写满。p73同时警告，结束处新增一个像接收音的音头，可能让人误认重奏。因此不能只抽出“短弧更干净”“括号更清楚”便批量替换。

## 2. 什么时候值得在新行重述音高

先确认仍在持续，再问读者是否需要回看前行：前面隔了多少活动、保持的音与新材料是否容易混淆、提示是否会挤占正在弹的层。若状态仍清楚，原范围线／文字已足够，可以不再补头。普通制音踏板会共同留下许多音，不能照搬选择延音踏板的具体持音清单。

新行恰好是原范围的终点，则不是同一个情境：在这里补“仍保持”的头，可能把结束读成继续。除非另有明确说明，不能用软件挂接点或纸面弧尾推定脚在某个毫秒释放，也不能让新增提示隐含延长范围。

**用户m132–135当前保留。** 作者已明确选择延音踏板保持A八度、两条长弧表示持续；源四音和弦的外层是A，内侧还有C♯、E。不能因为提示挂在一个Chord上，就把四音全当作作者指定的捕捉集合；也不把两弧逐条对应到两枚A，这层对应未由作者指定。

两个原生Slur从m132 q1/2接到m135 q0，后者是下一系统的接收边界。现有证据没有进一步给出手离键的确切时刻或捕捉／释放过程。因此本轮不在m135自动加括起音头、不隐藏接收休止，也不重编CC66。这里需要的后续判断是“是否仍跨过这个边界保持”，不是重新询问S.P.是什么或两弧是不是分句。

## 3. 官谱帮助分清了哪些条件

**A021《Bloody Stream》p4 F及下一系统：** 和弦后的开放弧伸入休止区，运行和较大乐句另有弧。它让持续背景与正在运动的层分开，不必把所有曲线都画成头到头的完整tie。当前没有工程和动作说明，不能据开放形状认定是中踏板、自然余响或精确释放时刻。

**A056《Here》p8第三系统：** 上部保持写有完整tie，下方同时有sost. Ped.与sus. Ped.，释放星号分层。持续、两套踏板和活动运行各有线索；不能为“少墨迹”把完整tie换成一根文字线或去掉第二个释放符。sus.的命名疑点仍保留，不因喜欢官谱就照搬全部简称。

**A059《Homura》p5：** 行中J的Adagio sostenuto属于速度／性格语境，前面还有mp sost.；页内也有括起音头。词根sost、括号或空心头本身都不能证明是选择延音踏板提示。应查完整词组、层的作用及持续关系，而不是按关键词绑定软件控制。这一页并未给本轮一个可确认的中踏板续行范例，不能为凑同类案例而强归类。

## 5. 交换身份的正反例

[MusicXML官方定义](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/cue/)区分不播放的cue身份和字形大小；会发声的普通音也可以写成小尺寸。具体大小另由[type的size属性](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/type/)表达。因此“小”与“不播放”不能在知识库中合并成一个布尔条件。

本宿主实际将括起小提示导为`cue`加`notehead parentheses=yes`；导回后两个音仍小、仍不播放，四个括号Symbol也保留，实际34次起音的时间／音高／力度序列与导出前一致。普通大小的控制却未导出cue身份，导回后失去不播放设置，m5多出两个A起音，总数36。这是本输入与宿主的实际差别，不推广为所有版本／所有导出组合。

**提示身份保住不等于整个往返无损。** cue版整个MIDI字节仍不同：释音长度及初始化控制／声像发生变化；图面位置也改变，新行原有`(Sost. Ped.)`继续文字未保留。不能以34次起音相同宣布播放和布局完全保持，更不能用这个交换文件替换用户原工程。当前只是为后续适配留下具体正反例，没有开发导出补丁。

## 6. 对自主净书的要求

处理持续时分别记录：已奏过的音、手是否仍占键、由谁保持、当前是否仍在范围内、是否需要提示，以及软件的播放身份。作者指定的捕捉子集不能由一个和弦容器替代；用户说明已解决的含义不再列未知，未给出的动作时刻也不擅补。

试验本身先核有效性。本例首稿把TextLine放在Chord内部，实际没有画线；改成voice时间位置后才成立。另一首稿把dots写在durationType之后，宿主把休止按2拍读入并自动补1拍；最终修正顺序，并核唯一休止实际3拍。两个无效构造均私有保留，不能拿它们说明宿主不支持持续线或原音乐有问题。成功退出、MIDI音数及整小节合计都不是充分验收。

本轮用户PDF／MSCZ保持原样，旧休止试验仍不采用。后续Muse适配需能表达持续角色、捕捉子集、提醒与新攻击的区别，并分别预览原生／交换结果；本次没有改MuseScore、MCP、插件、字体、GUI或全局安装。
