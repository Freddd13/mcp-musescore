## 1. 三条弧线：避开碰撞，还要让人看出连的是谁

[Beauty contests](https://lilypond.org/doc/v2.26/Documentation/essay/beauty-contests)把同一音型的三条弧并列：较低者擦到中间音头；抬高之后避开了音头，端点却更远；末版也仍有端点距离和走向的代价。它说明候选往往只能作有理由的取舍，不是每一项都同时最好。

**源码带来一个关键限制：** 三个数15.39、13.08、12.04是片段中手写的文字标签；前两版还分别强制Slur.positions，末版未作该强制。它们是官方教学例中的解释，不能说成这次运行2.26评分器得到的测试数据，更不能拿来作我们的验收阈值。没有从截图反推出当前引擎的全部目标函数。

本线据此采用的判断：先保护真实连接和可见归属，再比较净空、靠近程度、轮廓与空间代价。若现有候选都读不清，应扩大局部预算或换一种路径，而不是在有限候选中硬选“最不差”便称解决。这是本项目的方法，不声称LilyPond把以上项目全部实现为硬约束。

与[跨表弧原生例](CROSS_STAFF_SLUR_ROUTING.md)相接：绕到梁外有价值，端点仍须指向原来的层；改变表距又会影响整行高度。仅使碰撞数归零，不足以通过。用户S.P.长弧还有持续功能，更不能先作为普通分句弧优化。

## 2. 对照出版谱，是学习可接受的解，不是复制一张标准答案

[改进基准](https://lilypond.org/doc/v2.26/Documentation/essay/improvement-by-benchmarking)的旧版／新版对照，同时涉及干长、线重、弧、局部宽度，以及原先缺失或不同的音乐信息。因此可学它怎样定位问题，不能将综合改善归给字体或某一个参数。本批只核官方给出的图和当前片段，未运行旧版。

[BWV861对照](https://lilypond.org/doc/v2.26/Documentation/essay/engraved-examples-_0028bwv-861_0029)实际包含四种出版图及两个软件图。四图不是同一输入的纯排版变体：官方说明其中一版来自另一音乐来源，Busoni版的部分编辑标记也被移除。可比较声部追踪、休止位置、梁干与分行；未逐音校勘，不以像素／弧线数判某版错误。

本批可见：Bach-Gesellschaft截取图的首小节在第一条短行末端，随后另两行展开；其它图多为3＋4小节的两行。截取所处的原页位置不明，不能从这张不齐的片段判其原书浪费空间。相同出版者的两版也存在可见细节差异，所以“像官谱”应指向阅读组织及风格范围，不能成为逐坐标模仿。

[软件比较页](https://lilypond.org/doc/v2.26/Documentation/essay/getting-things-right)比较的是Finale 2008，并已改纸幅、强制两行；不属于完全无设置干预，也不代表今天各软件。图中的同表双声部可在没有实质碰撞时仍难辨归属；跨声部必要变音则属于读法正确性，优先级高于外观。不能由旧图认定本机MuseScore有同样缺陷。

## 3. 页内稳定与页内网格，为什么不是一回事

[起源章节](https://lilypond.org/doc/v2.26/Documentation/essay/the-lilypond-story)用两页大提琴谱和小节线示意讨论机械重复的页面。可见两页均有规则的短音型，却有不同的局部分配和弧形；它提出回看时的定位问题，但本批没有进行读谱速度实验。

本线的取舍不是故意制造参差。**一组内部的跟读稳定、相似材料的可识别再现、整页的小节线对齐，是三个层次。** 对应材料和预算接近时，重复布局可帮助认段；内容／占位不同还硬对小节线，则会把不必要的压缩或拉伸转移到组内。应先解释本行读者在追什么，再决定哪些稳定、哪些容许变化。

[Akuma整曲](INTEGRATED_READING_AKUMA.md)的相似再现分配可保留，[Madoka组曲](INTEGRATED_READING_MADOKA.md)各段容量又随拍号、活动层改变。它们分别反对“所有行都应不同”和“固定四小节才整齐”；不是从LilyPond示意推出用户应采用某种页面网格。

## 4. 对用户关心的间距，怎样应用这些知识

以下回用已验证案例，没有重跑原生实验或增加迁移成绩。

| 实际情境 | 先保护／解释什么 | 能比较什么，怎样拒绝 |
| --- | --- | --- |
| [五连原创例](FIVE_FOUR_SPACING_STUDY.md)：另一表在组中进入 | 两组单位、真实插入及共同点；默认同步本来正确 | 比较确定区域内的脉冲稳定与必要净空。现有候选只在当次预算成立；窄版仍换行，不说局部头距已修复全局预算 |
| [12对11原创例](POLYRHYTHM_SPACING_STUDY.md) | 真正共同开始／到达与中途谱号；不能逐头吸齐 | 移一头虽保MIDI却破坏汇合，藏谱号虽更匀却丢读法；两者均拒绝。另一候选重分预算仍未显著改善，本例保留默认 |
| [T02实曲页](SKILL_TRANSFER_SPACING.md) | 多数组近稳，行中谱号需要空间 | 当前保留；有占位原因不等于已证明最小宽度，也不能据最大／最小比率排序美观 |
| [用户tie线重副本](CURVES_STUDY.md) | 持续连接和弧层次、有效样式 | 字形不变时也能改变黑度。已有候选的短端、打印与连带对象仍有限制，不从“新版更粗”直接套全谱新值 |

这把“为什么不匀”与“该不该改”分开：联合时间列的机制能解释症状，却不替我们决定可接受程度；一个较整齐的候选也不证明音乐、可见读法和后文预算都保持。未来改进应减少没有阅读收益的波动，同时保留必要不匀，而不是把共同列或头距方差当唯一目标。

## 5. 内容、符号与图形控制，分清后才谈自动化

[音乐表示](https://lilypond.org/doc/v2.26/Documentation/essay/music-representation)的异拍／跨表例与[模块示例](https://lilypond.org/doc/v2.26/Documentation/essay/what-symbols-to-engrave_003f)显示：同一个音乐层可跨表，一张谱表又可承载多层；增添谱号、干、变音和弧不只是把点画漂亮。七个模块图的共用音乐定义已另核，首图主动撤除多种模块并压平谱位，是分解示意，不能作正常成品的排版缺陷。

[可调结构](https://lilypond.org/doc/v2.26/Documentation/essay/flexible-architecture)的线重对照同时改Beam、Stem、Bar、Tie、StaffSymbol及tie偏移；另一图有意将音头换成字母。它们证明可控范围，不证明这些组合漂亮或可直接映射到MuseScore。include自身的version2.19.21也是语法声明，不是本批文档或实际编译器的版本。

[光学尺寸](https://lilypond.org/doc/v2.26/Documentation/essay/optical-sizing)第三图补看了同页不同大小谱表的组合；[字体页](https://lilypond.org/doc/v2.26/Documentation/essay/music-fonts)则提醒字形重量须与线、梁和弧配合。这里仅把它们作为布局输入及输出条件，字体设计仍由另一条线处理；没有做打印或字号最优值实验。
