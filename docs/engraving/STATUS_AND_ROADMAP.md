## 这次收尾解决什么

1. 把旧逐轮进度与安装历史移至同目录的历史文档，当前入口只保留当前能力、使用方式与真实差距；历史内容逐字保存。
2. skill的30段逐例条件移入按情境读取的参考，主流程与全部知识保留；20个专题入口及查询方式保持。
3. 汇总已知技术缺口、未定音乐含义和风格候选，明确它们如何影响当前判断，不为发布继续无止境试排。
4. 提供带校验的知识库／skill整包、固定Git标签和一次关联安装。用户原件及私人研究缓存不打包。

本轮详细结果和验证范围见[首版使用示范](V1_TRIAL.md)及[发布证据](release_1_0_0_evidence.json)。

## 现在怎样试用

先给一份完整PDF或一个明确范围，让skill提出少量有理由的保留／改进判断。需要候选时再用副本比较。你主要看：是否抓住真正影响阅读的位置，解释是否可信，建议是否符合审美；不需要逐条审核规则或先安装／打印。

可直接复制[使用说明](../ENGRAVING_SKILL.md)中的提示。个人细微取舍通过真实反馈积累，不将一次选择推广成全谱预设。没有自动启动后续扩读或开发。

## 后续完整路线

| 阶段 | 做什么 | 开始条件／完成依据 |
| --- | --- | --- |
| 当前：首版试用 | 在你的实际谱子上诊断、解释和少量原生候选 | 你能看到有价值的发现，合理排法没有被误改 |
| 开发1：核实际能力 | 对照当时muse3 dev、插件／MCP的结构、单位、样式、坐标及范围能力 | 试用认可并确认开发范围；从已有具体复现出发 |
| 开发2：只读诊断 | 先输出位置、问题、依据、未知项与建议 | 有代表性谱例和误报／漏报对照 |
| 开发3：副本候选 | 局部调整、原生预览、整行／全曲连带、保留原样与人工锁定 | 音乐、记法、保存／撤销及实际读法均保持 |
| 开发4：有限自动净书 | 先做已验证的高收益外观操作，记法改变单列 | 可解释、可撤销、失败可恢复；不默改演奏含义 |
| 开发5：系统／页面 | 联合密度、重复材料、导航与翻页安排 | 优于固定小节数模板，包含不同织体反例 |
| 必要能力补齐 | 优先现有属性／插件，MCP负责调用，必要本体改动最小化 | 只有已复现且既有控制不足时进入；按AGENTS维护指南、日志与提交 |
| 持续迭代 | 补资料、修正判断、积累个人选择 | 由实际任务需要触发；九项外部缺口暂缓 |
