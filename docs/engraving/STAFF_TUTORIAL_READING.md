## 增加空谱表与拆分已有音符，解决不同的问题

**净书先判断读者需要追踪哪条音乐线，再决定放在哪个谱表。** 教程标题里的“增加声部”主要落实为增加／拆分谱表；这批预览没有提供完整Voice1–4录入流程。

| 预览标注时间／格 | 直接可见的内容 | 可采用的判断 |
| --- | --- | --- |
| 50–70秒／6–8 | 乐器窗口右侧为Piano与Staff 1，窗口显示Add Staff和Add Linked Staff两个入口 | 先确认是在已有乐器内加谱表，还是另加一个乐器；两个按钮同时出现不证明作者都操作过 |
| 80秒／9 | 原高谱表下出现低音谱号的空谱表 | 先增加容纳独立内容的位置；空表本身没有完成声部或用手分配 |
| 190秒／20、240–260秒／25–27 | Split Staff对话框及Split point音高输入 | 这是按音高分配已有内容的操作，需要另核音乐线的连续性 |
| 270秒／28 | 双谱表的结果画面，原有音乐内容分布与空表状态不同 | 可确认演示涉及拆分，不能仅凭这格认定全部时值、连接和标记已经正确迁移 |
| 350–390秒／36–40 | 同一练习中的音符、弧线和检视器 | 几何连接和音乐归属需要继续检查；不能把画面上所有弧都解释成跨谱表命令的结果 |

MuseScore的谱表、Voice容器和音乐角色分别记录。同一谱表可以同时承担持续声部与活动声部；一条连续音型也可能在两个谱表间显示。关联谱表用于共享音乐内容的另一种显示，不适合拿来创建独立伴奏。上述概念与[3版手册的乐器／关联谱表说明](https://musescore.org/en/print/book/export/html/278625)及[多声部章节](https://musescore.org/en/handbook/3/working-multiple-voices)交叉核对；本教程预览不替代这些概念的实际工程验证。

## Split Staff的作用范围，比局部选区大

**不能把Split Staff当成“只美化选中几音”的快捷动作。**

本机Evolution源码快照中，`Score::splitStaff(staffIdx, splitPoint)`先在同一Part内增加谱表，设置低音谱号，然后从首个ChordRest段遍历到全曲末尾，检查四个Voice。低于分界音高的音符移到新谱表对应Voice；等于分界音高的音符留在原表。函数没有接收所选小节范围，也没有按选择的终点停止。时值、休止和连接还有相应迁移处理。

核查位置：`libmscore/score.cpp:2573–2730`，调用处`mscore/scoreview.cpp:517–520`，对话框`mscore/splitstaff.ui`与`splitstaff.cpp`。快照HEAD为`8f81421a5cc965dbb32a81fcecf39d626b5610ff`，四个所查文件没有工作区修改，文件哈希见证据。这是只读源码核查，没有证明某个正在运行的exe与该快照对应，也没有验证所有连接都能正确保留。

它适合对原本混在单谱表中的内容做初步整理。作为钢琴终排策略，固定音高界线有明确代价：完整琶音可能跨过界线，交叉旋律也不按固定高低决定用手。应先确定保持的音乐线、独立时值与用手提示，再选局部跨表显示、换号或分层记法。

### 怎样用于已有谱例

| 情境／触发条件 | 优先动作及理由 | 例外与检查 |
| --- | --- | --- |
| 一个连续音组在两表间移动，读者需要保住方向和组界 | 先检查显示换表点、梁／干、数字与加线，不先重分整个源谱表。已有[m97平衡版](M97_GROUP_BOUNDARY_TRANSFER.md)保留源显示分配，同时处理六连范围和两向干长 | 用户初步喜欢原方向，尚未采用新方案；加线与分梁仍有代价。此处是复用已有经验，没有新增实曲试验 |
| 同一谱表有长值与运行音，音区互相穿越 | 先按各层真实时值、入口和持续关系辨认；需要时单列Voice／记法提议 | [分层复拍子案例](LAYERED_COMPOUND_READING.md)的共头双干与独立保持说明，仅按高低拆分会漏掉读者任务；PDF不能提供工程Voice的完整证据 |
| 从单表素材准备钢琴双表，考虑批量按音高拆分 | 可作为输入整理候选，先在副本核整条源表的作用范围，再回到完整乐句审查 | 保护音高、时值、共同起音、休止、tie、slur和标记所属层；当前没有新增该命令的运行／撤销验证，不自动写回用户工程 |

## 图形补法可以成形，音乐含义和依附还要另核

作者简介还说明要处理软件未收录的古谱罕见记号。470–500秒（格48–51）可见符号窗口中的分类、搜索及符号选择；510–580秒（格52–59）反复调整位置和堆叠顺序。610–710秒（格62–72）能看到线宽、线型、端点和短斜线的组合。800–860秒（格81–87）谱面出现“PNG图片”文字并有检视器操作。

**本次只确认这些可见手段。** 预览没有可靠读出罕见记号的名称／奏法、每个对象的父项，也没有展示完整保存重载结果。“PNG图片”几个字不证明画面已嵌入一张PNG；选中外观也不足以辨明所有载体。

用于净书时，可以从符号库、文字或图形组合补足显示，但应保持两份信息：演奏者实际读到的指令，以及工程里真正控制时值、重复或播放的结构。3版手册区分普通Symbols类别的图形符号与有专门功能的记谱对象；形似反复号的图形不会因此自动建立演奏路线。[手册：符号与记谱类型](https://musescore.org/en/print/book/export/html/278625)。

对未来自动净书有用的检查是：

- 先按图例和上下文确认符号的阅读任务，再选显示载体；古谱字形不直接套现代钢琴含义。
- 移动符号时，核它应跟随的音符、小节线或范围；堆叠顺序只处理遮盖层次，不能确定归属或连接。
- 把“当前这一行摆得像”与“换宽度、换行后仍正确”分开。已有[跨线显示组合](CROSSBAR_DISPLAY_COMPOSITION.md)说明，原生保存稳定仍可能在换行或交换时失效。
