# 音高拼写：少一个重升，不一定更容易读

2026-10-21。完整读取并看Gould印刷p77–79、85–87图文，后3页为复看；章页／目录只作定位。复看A062《Idol》与A065《IRIS OUT》各p1–3及目标系统，再用原创短例作MuseScore原生比较。原书、官谱、用户工程只读；[证据](accidental_spelling_evidence.json)区分音乐拼写、可见事实和原生实测。本阶段没有软件适配或字体制作。

## 1. 净书是在帮助读音程与动作，不能只数符号

十二平均律钢琴中，F重升和G还原可以对应同一个键，但它们在谱上占不同位置，与邻音形成不同的书写音程，也影响后续变音怎样确认。把二者换写属于记法提议；数值音高和MIDI相同，不能使它自动变成纯外观优化。

Gould p85的拼写建议需要合在一起使用：尽量采用熟悉的纯、大、小音程；级进型尽量按相邻字母写成音阶；半音阶型常用升号上行、降号下行；重升／重降若能说明和声，没有一概回避的理由；同一乐句中尽量少作破坏阅读轮廓的等音切换。该页虽在无调性小节下，正文明确这些习惯也用于有调性音乐。

因此不能只背其中一项。旋律整体上行不等于所有变化音都改成升，下降的和声低音也不要求全部换成降；另一方面，出现重升也不自动证明原拼写最好。应先问它保存了哪种级进、和声或重复型，换写后读者要重新辨认什么。缺少这些帮助、实际形成生硬跳进时，仍可比较另一种拼写，单列记法理由。

### 字形和变音制度也有阅读成本

p77–78把变音的核心形状与所在谱线／间相联：升、还原的斜横画，降号的圆肚，重升的叉形各有识别任务；外框并非它们唯一的归属线索。过小的变音在远处或光线差时难辨。不能为挤进一行单独缩小普通音符的必要变音；书中缩小符号的条件是装饰小音或cue等相应字号。本轮不把书的比例描述写成所有字体必须使用的几何常数。

p78–79还说明通常小节制下的状态参照：不同八度、换谱号或同音转到另一个谱表，需要相应确认／取消；同一演奏者在同一表上改由另一只手接，不因此自动重置变音；同一人同表的不同声部通常共享变音状态。多人共表又有分别确认的阅读需要。不要按“手变了”“voice编号变了”统一补符号，也不要跨表只凭同MIDI音去重。这里只核规范条件，没有用当前宿主验证所有换号／跨表状态策略，不能据此报软件缺陷。

p86–87对逐音变音、只影响紧随音、连梁／重复型例外又有不同约定，必须明确且一致。它们可能降低记忆负担，也可能让符号过多或让无符号音含糊；不能从某一片段较省符号就给普通钢琴曲换整套制度。更多实际来路与提示案例见[变音上下文](ACCIDENTAL_CONTEXT.md)。

## 2. 官谱里的重升在帮助读什么

**Idol：书写三度比少用复杂符号更有价值。** A062 PDF p2，B起点的第1系统首小节下表，第3拍附近可读到F重升八度与D升构成的和声音型；前面有G升八度，后续又出现普通升号的确认。按谱号和调号读，局部包括`F𝄪2–D♯3–F𝄪3`。D升到F重升是大三度；若把F重升改成G还原，同样四个半音会写成减四度，八度层与和声形状也随之变化。

保留此拼写有明确阅读理由：内层与外层的和声关系较容易识别，重复出现时仍有相似参照。不能仅因整句低音下降，就套下降用降号去改它。这里没有该曲工程、播放或全段和声校勘；不由这一局部给全曲指定唯一调性分析，也不据PDF反推voice编号或自动变音算法。

**IRIS OUT：下邻音的组形反复出现。** A065 PDF p2，C首系统第1小节下表的短运行，包含`G♯2–F𝄪2–G♯2`；相似的回转型在后续伴奏反复出现，p3仍可连起来读。它把中间音写成相邻字母的下邻音，回到原位的形状一眼可追。改为`G♯–G♮–G♯`仍可指向相同键，却变成同一字母的来回变化，需要另一种变音确认；未证明一定更省宽、更容易跟读。

本轮保留这两处有理由的原拼写，未将官谱用了重升推广成所有重升都该保留。也没有逐音校对全部六个已看页面；读者收益是结合可见音型和规范作出的解释，不是制谱者意图自述。

### 相同MIDI究竟保护了什么

两版的17个数值音高、起点和名义时值分别与独立配方一致，实际17次MIDI起音也核对，完整MIDI逐字节相同。原生输入除精确定位的两个tpc外一致；**拼写按预期已经改变**，不能把播放相同写成音乐／记法全部未变。

功能版实际原生保存重载，17条拼写／时值记录、原生pitch／tpc、完整MIDI、去标题SVG及原始RGBA均保持。换写拒绝版只核初次原生输出，没有做其保存重载；没有MusicXML导回、试听、打印、读谱速度实验或用户审美采用。原生宿主为固定`7b4e6fbf…`二进制，未由版本号推断源码提交。

这不是证明MuseScore自动排得差的例子：它是在正确处理新的拼写及必要错头。应拒绝的是为了减少复杂符号而擅自换音名的美化策略，不能把其后果当间距引擎失误。

## 4. 以后怎样用于自主净书

遇到密集变音，先读整句、调号与局部和声／邻音关系，决定哪些拼写承担识别任务，再检查列内净空、时间间距和行宽。已读到的正常和声叠置与重复组形，可给出保留理由；含混处提出记法疑点，不先自动换写求窄。

若确实建议等音改写，明确比较读音程、记忆、重复型和确认符号的收益与代价，并核所有后续自动符号、邻位错头及行页连动。它属于记法候选，即使pitch／完整MIDI不变，也按该范围记录；用户明确要求移调／重拼写时再按实际任务处理，不把本例变成一律禁止换写。

后续工具应保护拼写及数值发音两个层次，不能从MIDI或12个音级重建原音名。当前skill只接入判断与反例；本轮未开发自动重拼写、MCP或本体接口。真正的间距空间仍见[变音列](ACCIDENTAL_SPACING.md)与[间距取舍](SPACING_DECISIONS.md)，字体改造另线进行。
