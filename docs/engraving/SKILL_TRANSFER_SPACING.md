数据来自同一源PDF、同一子集字形和字号的正常侧头原点，结合原图识别，不用和弦外框中心，也不从字体字符码推导时值。原PDF的子集名字不证明字体家族或制作软件；没有提取嵌入字体。文本advance框也不是实际墨迹净空，不能用它直接认证可缩量／碰撞。

若把第三小节最大格12.468pt摊到15格，首末跨度会从约148.920pt增至187.018pt，多约38.098pt、25.6%。这是固定组内容的**算术代价**，不是已渲染的改版，更不证明这种方案必定增页。它说明“按最宽格全组等距”会让其它本来清楚的间隔付出明显宽度；另一方向全部压回普通格，也可能让谱号缺空间。局部预算和整行代价应一起比较。

## 3. 两表对齐检验，不能只挑视觉最近的头

先从实际旗梁、附点与连接读书面时位，再取对应的正常侧头，不能用测得X反过来给音符分配时间。

- 第2系统第1小节：低部16个十六分位置，上部8个书面时位为四分单位q=0、0.75、1、1.5、2、2.5、3、3.5；所查8列对应。
- 第5系统第2／3小节：上部各16个十六分位置，低部各10个书面时位为q=0、0.25、0.5、0.75、1、1.5、2、2.5、3、3.5；各查10列对应。

合计28个共同书面列在源PDF记录精度下X差为0。**其中包含tie接收，不把28列称为28次共同新攻击。** 这支持保留这些关系，不证明全页每个音都已核对，也不证明原生voice、tick或MIDI实现。末音到小节线、谱头和跳转／预告的边距不混入组内均匀度指标。

## 4. 规范复核怎样改变下一步

本轮完整复看Gould印刷p40、41、43、491，全部为旧实质图文页，不增加311/696累计。

p40将普通节奏空间与机械时值比例区分，同时要求同一系统中同值保持均衡；p41说明干向相对关系会影响均匀感；p43具体讨论额外谱号和变音：先压实周围可用白空间，确需时才扩宽，不为让所有音同距而把全组按最挤处摊开；p491要求以正常侧音头核共同列，不能移整和弦去对齐错头。

因此本例不能总结成“有谱号便接受任何宽格”，也不能总结成“1.298超阈值便必须修”。当前合理决定是保留音乐、共同列、变音与多数稳定快组；若取得可编辑输入，再固定同一字体／行宽比较谱号周围留白和该局部时间空间，读回前后两手及整行。前置符号压实、局部时间列分配和移动谱号的音乐位置是不同动作，不能混在一次拖头里。

旧[A132记录](corpus/READING_023.md#a132this-game2021-ver8页)只对p3／6／8及与2014版的不同编配作解释，没有给本页间距的独立答案，不能拿它当准确率标准。也未读取A131来凑对照：不同编配、音型和断行的两版不是仅换排版引擎的A/B。
