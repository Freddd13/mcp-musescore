# 变音列、错头与时间间距：紧凑到哪里才有意义

2026-10-19。由用户关心的“变音和两手对齐使间距忽宽忽窄”继续研究。来源为本地Gould印刷p59、85–92完整图文及p60复看、A127《The Rumbling》p1复看、当前Evolution原生实验和只读源码。p54–58、p47–53及p491的先前学习仍需合读，见[符号细节](NOTATION_DETAILS.md)、[间距取舍](SPACING_DECISIONS.md)。哈希、实际读取范围、测量及保护见[证据](accidental_spacing_evidence.json)；教材与官谱图仅在本机缓存，不入Git。

## 1. 读音高和读节奏，需要分别安排空间

读者先要看清哪个变音属于哪个头，再识别连续音的节奏轮廓。前一任务需要符号与头靠近、各列可辨；后一任务需要合理分配时间空间。压紧变音列可能释放宽度，却不保证释放的宽度会分到最需要的音组；必要变音也不能为了匀称而删除。

Gould p85–87还涉及拼写和变音记忆策略：熟悉的音程、级进字母和乐句内一致性帮助认音。传统小节内有效、每个不同音高确认、只对紧随音有效等是不同的编辑制度，各有简洁与记忆负担。不能看到临时记号多，就自动等音改写或删“重复”；这种改动属于记法提议，不是外观调整。p87无小节线的条件也不能移植为普通钢琴小节的统一规则。

### 为什么变音列不是从上到下排一条阶梯

| 情境 | Gould的条件与阅读理由 | 错用后的代价 |
| --- | --- | --- |
| 两个变音相隔八度或更远，p88 | 可竖向成列；六／七度还须看真实形状是否接合。上方为降号时，部分组合比升／还原号容许更紧 | 一律错开会浪费宽度；一律对齐则可能把两个符号连成难认的一团 |
| 五度以内，p88 | 通常高者靠头、低者向左；某些轮廓可嵌入彼此空白，但升号竖笔不可接合 | 仅按矩形框禁止重叠会过松；忽略墨迹则过挤 |
| 三音以上密集和弦，p89 | 由高、低再剩余高、低交替安排，利用上下空处；宽和弦可让外侧或八度配对 | 从高到低一直向左铺，容易变成不必要的宽阶梯 |
| 含相邻音，p90–91 | 变音顺序有时跟着错头方向更好认；密集时仍可采用较紧的常规交替法。两部交叠还须靠各自的头说明归属 | 为形式统一而重排，可能使符号离自己的头更远或看似属于另一部 |
| 下干错头，p90 | 有空处时，部分变音可以靠近干，而不是全部被最左边的头推远 | 以整个和弦矩形当不可进入区域，会放弃可用的白空间 |
| 变化同音、两部相邻，p91 | 需辨认每部的变音；尤其已有tie的延续不能因另一部的还原号位置而看似改音 | 只查最终发音或最小外框距离，会漏掉视觉上的错误归属 |

这些不是所有组合的唯一模板。字形轮廓、音域、错头和多部关系会改变可用方案；最少列数也不能压倒归属。p92的**调号**又是反例：降号之间可贴近，但仍要保持整个调号的均衡，不把某些四度组合单独塞得特别紧。和弦变音列的局部嵌排，不能不加区别地用于调号。

## 2. A127 p1：哪些不对称应该保留

复看整页及首两系统放大图。第一系统最后小节、第二系统首小节，上部半音双音／和弦交替，可见上下相隔较远的同类变音成列，邻近变音向左错开；第二系统还有向干两侧错开的相邻头。下部同时有附点、短细分及tie连接的低音，不能只按上部每组的图形中心安排时间。

**阅读收益：** 靠近的变音与头先组成一个可认的音高单元；远隔的变音共列减少横向负担，近邻错开避免笔画粘连。错头则让相邻音各自可见并连到干。梁和重复型提供节奏分组，使读者不必从每个空白的毫米数猜拍子。这是结合图形与规范作出的阅读解释，不是出版者亲述操作。

**为何不建议直接“修齐”：** 统一所有变音左边缘会扩大某些组，统一整对符头中心又可能挪错时间参照；将附点／tie当成多余黑点删去会改变持续读法。本次没有发现足够证据把这些合理错列判为官谱错误，也没有该谱工程来验证每个voice或内部定位。局部排法可取，不代表该页每一段间距已证明最优。

## 3. MuseScore已经做了什么，参数又改变了什么

只读本地`libmscore/layout.cpp`：`layoutChords3`已经识别八度列、交替安排未配对变音、处理下干错头，并取字形`cutOut`信息；`resolveAccidentals`会在部分轮廓空处允许紧凑嵌排。不能将“加入轮廓感知”当作一个从未实现的全新解决方案。源码和实测二进制分别以哈希定位，未证明两者恰好同一构建提交。

还有一个参数解释上的陷阱：`accidentalDistance`既参与列内排布，`chord.cpp`约1974行又将它加到变音**前方**的占宽中。因此单改它，也可能改变只有一个变音的时间列与整行分配；不能把它简单称为“两个变音之间的距离”。`accidentalNoteDistance`则参与变音到头的空间。参数名、局部画法和最终时间间距是三个层次。

### 同曲、同字体、同版心的分离实验

**当前判断：不推荐0.10／0.10作为全谱预设。** 放大图中降号与符头更贴近，代价落在所有相应位置，不只问题拍。它部分缓解数值波动，但没有证明整体阅读更好。保留[联合实验谱](fixtures/chromatic-tight-accidentals.mscx)及[图](fixtures/chromatic-tight-accidentals.png)，与[原图](fixtures/chromatic-spacing-source.png)同裁框；它是参数因果实验，不是已采用的美化方案，也不证明原默认最优。本轮不再要求用户辨认这类微差。

核对：四版原生XML在Style外完全相同；各51个事件（50头、1休止）的音高拼写、时值、起点、谱表与当前MusicXML导出一致，原生版之间非布局MusicXML相同；16个两手共同音起点正常侧头同X。联合版保存重载SVG及PNG相同。均为1页1系统，当前基线图与已提交原图逐像素一致。未做打印、试奏、一般碰撞检测或用户审美验收；本例没有多voice、附点或连音，不能借此验证那些情况。

## 4. 二度和弦的外框中心，会制造假的“不齐”

重导既有原创[密集相邻头源谱](fixtures/dense-spacing-source.mscx)，复看[完整两手](fixtures/dense-spacing-source.png)。第一和弦四个头分成两列：正常侧绘制原点X=123.340pt，另一列X=128.636pt；下部同拍单音X=123.340pt。五个头的墨迹路径及缩放相同，因而可以直接比较。

正常侧与下手误差为0；整组符头的墨迹外框中心却比下手单头中心右偏**2.648pt**。这是错头增宽带来的合理不对称，不是发音时间错位。若把整组中心向左吸齐，就会把本来正确的共同时间列移错。此处测的是符头集合，不包含左边的变音，也没有假定所有和弦都按最左头作参照；下干或交叠多部需另判。它是Gould p491一般对齐规则在当前宿主的一例原生检验。

## 5. 后续诊断与优化的顺序

先辨认变音的必要性、拼写和确认制度，再识别正常头、错头、附点与各部归属。随后检查符号内部是否有可用白空间，再检查相邻时间列的必要净空，最后评价剩余空间如何分配到拍组及整行。相同的“忽宽忽窄”，可能分别需要保留、局部收紧、改变分配或少放小节。

后续软件需求应能解释某列为何取到当前宽度、哪一个形状限制了压缩，以及放宽／收紧如何连带影响另一手。现阶段只有上述具体参数与几何证据，尚未证明必须修改哪个核心算法，也不在本次扩MCP／插件／本体。附点归属和变化同音仍需单独原生情境，不能用本次无附点的试验冒充已验证；新增教材判断见[符号细节第9节](NOTATION_DETAILS.md#9-共头附点与分离附点是在解释声部不是数点)。
