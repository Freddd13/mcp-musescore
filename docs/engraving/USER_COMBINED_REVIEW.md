## 为什么这些改动可以一起比较

m50／52的小节预算改变整行分配；m86又在另一页重分局部列。全曲vertical spread、手工弧形和显示谱表会使相距很远的动作产生连带，所以分别通过的局部候选仍要重新看整曲。

这次建立三种输入：基线、只处理rit.／尾声范围的最小版、再加间距的扩展版。**扩展版第7、8页的绘图对象与最小版相同；最小版第1–6页与基线相同。** 扩展版第1、3、5、6页也与基线相同。这样能把间距的风格取舍与两个明确干扰分开，避免把所有改变一并称作“整体更好看”。

完整复看八页后，扩展版的段落进入、跨行弧、变音构型和尾声层次可读，未见新增明显遮挡。m49–52与m85–88的完整两手系统、m144–146及末页四表至题献均用同裁框再看；不擦掉边缘邻行墨迹。最初尾页裁框随候选空表减少而变短，切掉了题献；已改用两版共同的基线裁框并重新看图。完整原生PNG仍保持180dpi，整页JPEG仅作较小的浏览预览。

## 两个值得记住的新边界

### 共同时间列的设置，保存位置可能换谱表

输入扩展版在原生staff4、m86的第2、3、4个Chord后分别写3sp leadingSpace。原生保存后，仍有三个3sp：两个留在staff4第2／3个Chord后，另一个出现在staff3第2个Chord后。它们分别对应q0.5、1、1.5；q1.5是上下部的共同时间点。

因此，固定XML路径下从三个变两个，不能独自证明丢设置。此次同时核到了三个实际保存值、16个目标共同起点、全部八页保存前后绘图与像素一致，才判断保存保持。后续读回应定位小节、逻辑时间及共同Segment，并检查相关谱表；这一结论来自本输入和冻结宿主，不代替未来接口定义检查。

### 隐藏谱表的交换输出，也要保留具体差异

当前宿主的MusicXML在P3／m150新增如下内容：

```xml
<attributes><staff-details>number="2" print-object="no"</staff-details></attributes>
```

`staff-details`的这些字符处于正文，属性表为空。这是此次空表退出时实际出现的交换输出，未追查当前源码或其它版本。整树比较保留该确切位置及文本，单列为布局差异；没有把所有attributes或directions忽略掉，也没有将此MusicXML重新导入替换工程。未来软件研究可复现这一输入／输出情境，当前先保存证据。
