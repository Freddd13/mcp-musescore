## 1. 判断“稳”需要分清三种距离

**共同时间位置。** 两手及声部同时发生的事件应能在竖向找得到，先建立共同时间列。它不是每个符头都必须在同一X：二度错头、同拍不同部错列、装饰音等有合理局部位置。

**节奏的视觉步长。** 连续同类时值/音型应有可跟踪的节奏轮廓，但较长时值不按真实时长成倍放宽，也不能因局部加宽让长音看起来比短音更短。不同细分共存时，在有限宽度、符号净空与传统压缩间距下，常需在各层均匀之间取舍；并非数学上绝不可能让每层都等距，五对三的比例构造与实际反例见[续学](SPACING_DECISIONS.md)。

**实际墨迹之间的空间。** 符干、头、变音列、符点、旗尾、加线与谱号改变眼睛看到的疏密。符头中心等距仍可能忽紧忽松；反过来，微调中心位置可能让视觉更均匀。跨谱表共梁尤其需要同时看符干轴线和符头。

因此诊断不能只输出一个“相邻符头间距方差”，也不能把所有不等距都解释为合理光学校正。应说明差异保护了什么，是否确有空间需求，能否用更少扰动达到同样读法。

## 2. 教材核查：均匀有条件，避碰不是全部

来源：Gould *Behind Bars*，本机主PDF，印刷p39–43、87–88、489–490均看完整图页；PDF页码=印刷页码+20，仅用于本版本的已核页。

| 条件 | 本次掌握的原则 | 为什么、不能怎样套用 |
| --- | --- | --- |
| 一般时值空间，p39–40 | 长时值只比相邻短时值多占一些空间；教材给的是传统相对比例，不是1:2:4时间尺 | 给短音足够阅读空间，同时避免长音割裂画面；不能把比例图直接当sp默认值 |
| 同类时值与系统，p40 | 系统中同类时值应尽量稳定；加速或速度改变不构成按秒压缩的理由 | 给眼睛稳定的节奏参照；不同系统、密度和多层细分可需要变化 |
| 符干方向，p41 | 调整间距可造成视觉均匀，背靠背/向外符干会改变疏密 | 需连同音高范围、上下方向和墨迹看，不能只优化头中心 |
| 整小节单一时值，p41 | 无其它部细分的窄小节，单音可略偏左居中；宽小节及其它部有细分时另处理 | 平衡与同拍对齐的优先级不同；钢琴另一手仍在动时不能把长音自动居中 |
| 行首/小节边界，p42–43 | 第一音与调号/谱号应形成入口；变音不能贴得像调号，小节线与符干须可辨 | 行首、行中与紧排的限度不同；普通字符最低净距不能当所有连接处的规定 |
| 单个变音与换谱号，p43 | 尽可能不破坏节奏步长；有空间可压实符号周围而非拉开整组 | 降低突变；字形确实冲突时仍需增宽，不能靠负偏移遮住前音 |
| 多个变音，p43/87–88 | 通常需要额外空间；不应为了头中心完全等距而把整组都放宽。变音列依音区与形状紧凑排列 | 保护整体符号分布；同列允许与否取决于字形及音程，不能只按字符数计宽 |
| 两音变音列，p88 | 八度及更远通常可同列；六/七度视具体形状；锐角/竖线连成一体则应错开 | 白空间可以嵌合，但不能让升/还原的竖线粘成新图形 |
| 两手/多部细分，p490 | 每拍优先照顾最复杂的读法，其它层按共同时间对齐，再减小最大的失衡 | 此条件可解释某些不均匀，并非默认算法所有失衡都获免责；也不要求固定右手优先 |
| 相邻行的小节线，p489 | 本书建议避免相邻系统的小节线机械重合，以降低相似段落跳行风险 | “板正”应落实在节奏/组形/通道，不等于整页棋盘；此为作者建议，不自动挪开全部偶然重合的小节线 |

特别需要把p40的稳定目标与p43/p490的现实例外一起学。p43最后一组正反例明确支持局部为和弦变音加宽，而不把所有音都拉到最大间隔；这恰好说明“尽量稳定”和“绝对等距”不同。

m50平均步长比m52约大12.5%。release5工程只读核查：Staff4 voice1三小节各为六个八分，voice2各两个附点四分；Staff3 m50/52主层均为四分、八分、四分、八分，m51后半有十六分细分。三小节未保存measure stretch标签，但这不等于所有默认值/偏移/布局因素已经排除；标记与音高、密集层、曲线等仍不同。工程与PDF未证明每个对象一一对应。

## 6. 源码怎样解释现象，哪些不能夸大

只读查看本机Evolution源码：

- `Segment::minHorizontalDistance`，`libmscore/segment.cpp:2262`起：按各谱表shape取得最大空间需求，另加相应最小距离/边界规则。两手必须共享时间位置，所以一只手的冲突会影响共同列。
- `Shape::minHorizontalDistance`，`shape.cpp:81`起：按多个矩形的纵向相交判断水平距离，**已经能允许不在相同高度的图形嵌合**。不能把Dorico 2014文章中对其它软件的整列矩形批评直接当成本机MuseScore的现状。
- `Measure::computeMinWidth`，`measure.cpp:4654`起：已有向前追溯避碰，并会把额外空间分配到一段ChordRest；不是只检查紧邻两音。形状精度、回溯范围和分配策略仍需具体案例测试。
- `Measure::stretchMeasure`，`measure.cpp:3678`起：列的弹性为 `1 + 0.865617 * ln(t/minTick)`，用小节最短时间单位；先保护最低宽，再按弹力放宽。
- `Score::layoutSystem`，`layout.cpp:4315–4370`：系统剩余空间先按小节权重和basicStretch分给小节，再调用小节伸展。相邻同类时值的系统稳定性不能只在单小节优化。

关键可解释量：当minTick为十六分，一个八分时间列弹性约1.6，两个十六分列的总弹性为2.0；在未被最低宽截断的区间，共同八分脉冲可能得到 `2/1.6=1.25` 的空间比。它与自制原生探针、用户m51的测量吻合，形成具体机制解释。最低宽、非节奏列和系统分配都会影响其它情境，不能把1.25宣称为所有谱子的固定缺陷。

局部变音排法也已有复杂处理。`layout.cpp`有按音区配列、形状允许重叠的判断和距离样式；其中883行的cutout TODO是一个局部调查入口，不能据此说所有SMuFL外框/锚点都没有使用。后续真正的变音反例要比较实际墨迹、形状矩形、谱线/加线和相邻头，再决定改哪处。

本次在libmscore检索optical没有找到间距专用开关，但关键词未命中不足以证明不存在任何视觉补偿。跨谱表“符干均匀”的收益和现有行为还需独立fixture验证。

## 7. Dorico与LilyPond：借鉴机制，不靠品牌排名

[Dorico 6.2间距文档](https://www.steinberg.help/r/dorico-pro/6.2/en/dorico/topics/engrave_mode/engrave_mode_note_spacing_c.html)区分整体、局部段落、单个节奏位置与voice列，建议先调全局/段落再逐音修改。[跨谱表光学间距文档](https://www.steinberg.help/r/dorico-pro/6.2/en/dorico/topics/notation_reference/notation_reference_beaming/notation_reference_beaming_cross_staff_optical_changing_to_t.html)明确提供按符干而非符头均匀的选项（本次检索结果可读，直接打开返回cache miss）。这给出可检验的目标：局部控制与整体节奏稳定同时存在，跨谱表有自己的光学策略；不是“Dorico所有谱自动更好”。本次未安装/运行Dorico作同曲对照。

[LilyPond光学间距说明](https://lilypond.org/doc/v2.25/Documentation/essay/optical-spacing)用符干方向与小节线展示，数学上等距不等于眼睛均匀。这与Gould p41一致。学到的是同类图形的视觉关系，不是在MuseScore里硬抄另一个软件的默认数值。

## 8. 怎样应用、怎样形成开发目标

### 先有判断，不急着改引擎

诊断按拍/音型同时看上下手：同类时值的系统基准、局部真实细分、同拍列内错头、符干轴线、实际净空、行首/小节边界、变音列占宽，以及旧手工设置。输出“何处、为什么、有无必要、候选代价”，不把方差超过阈值当错误。

对于简单连续伴奏，优先保护脉冲稳定；复杂细分优先可读性，先试符号内部紧凑与局部渐进分配。小幅必要例外保留。若整理变音列已足够，不再动时间网格；若最低宽已经卡住，再考虑换行或多给空间。符干/符头方向造成错觉的情境另作光学校正，不能由通用等距覆盖。

### 当前可调的量各有作用范围

| 量/动作 | 合理用途 | 不能承诺 |
| --- | --- | --- |
| measureSpacing、单小节userStretch | 改整体/局部松紧，帮助容纳真实密度 | 单独保证梁内或跨小节同值间距一致 |
| minNoteDistance | 控制基本紧排的最低净距 | 调小就能把所有稀疏处拉匀；会影响其它情境 |
| accidentalDistance、accidentalNoteDistance | 调变音列内部与头之间的空间 | 用全局很小的值代替字形/音区的局部判断 |
| barNoteDistance、barAccidentalDistance及谱号边界样式 | 保持入口与归属、调小节/行首空白 | 把行首和行中混作同一最低间距 |
| Segment extraLeadingSpace | 有范围的局部额外空间/候选试验 | 当作独立时间列目标X，或保证当前插件读改已经可用 |
| 同类段落断行/小节分配 | 先给密集处足够空间、避免相邻行突变 | 固定四小节一行或固定小节宽就是出版品质 |

不先将所有音符单独拖动。若分开改两手offset，可能把共同时间关系弄乱，下一次重排也可能重新破坏视觉关系。

### 后续软件问题清单与验证方向

1. **已复现：细分改变导致持续脉冲空间变化。** 给自制探针及用户片段提出按拍/音型保持稳定的候选，在同一系统宽度下比较。目标是可读且稳定，不是全曲改成严格时间比例。保护碰撞最低宽，研究弹性、脉冲约束和局部密度的关系。
2. **待定位：同系统相似音型的小节之间粒度变化。** 以m50/52读法作入口，分别排除头/旗尾/文字/曲线、实际有效样式和小节权重。不能先怪字体或强行把m51也压成同宽。
3. **待复现：变音占宽超出必要或局部加宽过突兀。** 自制单升、重升、多列、加线、上下跳进样例，检查能否利用上下空白、cutout和合理列排序；参考谱只提供目标观感，不提供软件内部原因。
4. **待比较：跨谱表符干光学策略。** 头中心与符干轴线两种候选，维持同步列、stem/beam连接和显示谱表关系；先观察当前宿主，再决定最小接口。
5. **待受控：系统剩余宽度怎样分配。** 在相同音型连续段落中比较不同小节分配/松紧，保留乐句导航及实际读谱连续性；避免只把某个小节变漂亮、旁边变差。

先用离线读取、现有样式/插件候选及原生渲染证明改法有收益。若需要在保持同步和避碰的情况下控制时间列、而插件只能提供粗调或图形offset，才评估最小本体参数/能力；MCP只封装验证过的操作。当前不实现这些目标，不修改本体硬编码。

知识验收以能否分析具体片段、找到反例、提出理由和用户喜欢的候选为准；工具验收由本线负责语义保护、复现、稳定性和撤销。后续给用户的是少量实际图的选择，不是让用户去证明规则表完整。
