只读定位器的23项检查通过：源目录可从真实路径定位库；复制到含中文路径、离开项目后可由明确仓库／环境变量定位；错误显式位置不悄悄回退；专题路径存在；未知专题拒绝。源技能的目录联接在项目忽略目录内验证成功，未修改用户`.agents/skills`、MCP配置或当前GUI。联接文件访问通过不等于已在当前App里实际发现这个skill。

这些检查证明定位与引用工作正常，不证明模型会自动作出正确审美判断。详细结果及源文件哈希见[skill_validation.json](skill_validation.json)。入口路由和知识库保持单一来源，没有复制整库或打包原谱／教材。

接着按`notation`／`piano`专题检查用户既有副本m89、99、101、103，实际看完整原生p4／5和局部，得到[同音附点的保留判断](UNISON_DOTS_STUDY.md)。初筛仅看父note的print-object会误把隐藏头计为可见；原生字段、导出的notehead none和图形联合纠正。原创三版比较又说明：相同MIDI不能替代读法判断，自动与显式同值的头型会改变共头。这些认识已加入skill的原生保护参考；是同agent实际应用，未成为独立盲评或用户审美认可。

用A127《The Rumbling》PDF p3作同会话演练。它在全目录阶段已被阅读，未参与本轮原生候选调参，故不称陌生盲测。实际调用定位器的`piano`主题，复用本轮已读的入口／判断指南／钢琴专题，查看完整缓存图；当前原PDF哈希与渲染来源相同。原图只在本机忽略目录，未修改或加入Git。

演练问题是：“这页看起来很黑，梁与间距是否应更统一？只读给出理由和建议。”实际判断如下：

| 可定位观察 | 应作出的判断及理由 | 不应从中推出 |
| --- | --- | --- |
| F起，上部较慢的厚和弦与下表密集短音并行，下表还有低音保持／重奏层 | 保留不同干向、长短时值和局部连接提供的层次。密集梁黑度有音乐来源，先查层是否可追，而不是全谱减线宽 | 下表只能左手，或所有可见音头都应按一样的间距分配 |
| F附近有legato，快速组并非每组都额外加长slur | 文字与组形可以协作表达连续性，少画重复弧不等于漏写连奏；不为了“完整”给每组补弧 | 仅由PDF文字坐标就确认工程对象的精确作用域，或删掉已有局部奏法 |
| F区域多行每系统只容纳两小节；G附近较慢材料与前段收束共用一行 | 给实际密度不同的材料不同宽度预算有理由。若需要更疏，优先比较整体分行／尺寸候选和代价 | 全页固定四小节一行，或逐手拖成等距会更像出版谱 |
| 页上方局部八度线与外层分句弧的终点不同 | 各自提示音区与分句范围，保留其独立结束；不把线统一拉到小节线或同一接收点 | “所有跨度线应齐头齐尾”，或仅靠数字8识别全部音区对象 |
| F后局部r.h.与G附近上谱表l.h.提示 | 手接管需要就近标明；不能机械一表一手，也不能把局部手提示扩成整表范围 | PDF已提供内部voice／track编号，或允许本轮重分工程的手／声部 |

在这页可见范围内，没有仅凭“很黑”就值得直接改写的明确碰撞证据。因此结果首先是保留层次与范围，若确需改变再取工程和完整预算作少量副本。没有为了凑问题数量制造错误，也没有从参考谱抄一组坐标。其不足是没有此谱原工程、未做原生替代版／打印／试奏，不能把这个演练说成已优化A127。

## 初版边界与继续检验

skill能够把阅读任务、相关规范、具体例子和候选保护连起来；定位器只负责找到维护中的库，不打分或改谱。MCP操作能力仍按当前工具核查，不由skill名推断；PDF不能充当无损的编辑对象图。

下一步在真正的新任务里继续检验，特别是密集附点／变音、交叠多声部、复杂跨表和行页预算。独立行为评测尚未执行；三踏板／替指、实际翻页与个人细微审美取舍仍按具体材料补查。这些边界没有被23项路径检查“解决”，也不因此扩展本次范围去开发软件接口。
