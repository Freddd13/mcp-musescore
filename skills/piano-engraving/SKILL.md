# 钢琴净书

从演奏者正在辨认的拍组、声部、手、持续、标记归属和导航出发，判断哪里值得改、为什么、代价是什么。也应能有理由保留原排法。不要以参数表、规则数量、页数或几何均匀度替代阅读判断。

## 读取项目知识

本skill与`mcp-musescore`项目的`docs/engraving`知识库共同使用，正文只保存流程，不复制整个库。用随附只读定位器找到实际路径：

```text
python <skill目录>/scripts/engraving_library.py --topic spacing
python <skill目录>/scripts/engraving_library.py --topic spacing --query "变音记号 共同时间列" --limit 5
```

先读`start_here`中的`README.md`和`PREFERENCES.md`（本轮已读过则不重复）；`JUDGMENT_GUIDE.md`按相关情境读取，再选当前问题的专题。项目目录可用`--repo <路径>`明确指定，或沿用`MCP_MUSESCORE_DIR`；目录联接／符号链接安装会定位真实源目录。复制安装且离开项目时，须提供这个库的位置。定位失败应说明缺少哪部分，继续可独立完成的分析，不能声称已读库。

有具体问题时用`--query`取得少量来源段落、标题与行号，再读取相关上下文；关键词间可加空格，比例可直接写`6:3`。这是本地文本检索，排序不代表规范优先级或审美结论；先服从作者定义、再核规则条件与反例。未命中可换词或省略`--query`查看完整专题清单。原有不带查询的命令保持原用法，不建立索引缓存。

库入口链接当前发布范围与进度。学习尚未完成时仍可使用已核知识；未完成的材料、未经验证的推测须保留状态。需要汇报进度时按账本列本轮增量、累计X/Y及剩余项；使用固定版本时使skill和库来自同一checkout，不混用旧skill与另一版案例。

## 对当前乐谱作判断

先核当前作品／版本、乐器及演奏任务；视频／收藏列表须核作品ID、标题和作者，自动跳转后重新确认。同名官方PDF与视频成品分别记录，不用一份补足另一份未读范围。具体反例经`sources`查`SOURCE_IDENTITY_REVIEW.md`；跨乐器套用谱号、弧线或奏法前，经`notation`查`INSTRUMENT_CONTEXT_READING.md`的条件。

看完整系统和邻近上下文，再近看可疑处。PDF提供可见版面，不提供全部voice、手分配、播放或对象范围；OCR、字符码与外框不能独自证明音乐语义。有工程时补读结构和有效样式，区分未保存字段、实际默认与手动覆盖。

先采用本谱已定义的缩写和作者说明，音乐功能不能由软件对象类型代替。名称、作用范围与播放实现分别查；本谱A八度持续的作者确认见偏好记录，具体边界从上表“作品定义／持音”读取。

资料不一致时，先核对象、适用范围和本谱说明；区分一般概括的专门条件与真正的出版体例分歧，不按来源数量或年代自动判错。`sources`中的MPA对照保留了具体情境与备选边界。

把可见事实、规范条件、本次用户选择和待验证解释分开。喜欢新官谱不意味着它每处最优，也不意味着全谱等距、平梁或固定四小节一行。没有本次明确要求时，不擅自套这些样式；用户明确指定的形式仍应遵守并解释实际取舍。极简6/8对照“暂时看不出差别”只表示那一例收益未确认，不形成等距偏好。

报告先给保留／调整的判断，再讲关键原因和下一步，优先选择阅读影响大的具体位置。仅说明会影响决定的限制，集中说一次；避免反复限定和自证。解释读者要认什么、当前哪里影响识别、可行方案及空间代价。音乐本身的密度、必要变音或故意切分不应被当作软件错误。熟悉的节奏不必过度拆分，真正独立的层也不能为了简洁删掉提示。

区分外观候选与记法提议。重分voice／手／谱表、改谱号或时值、拆合休止／tie、增删提示变音、改变拍组可能影响读法；单列解释，按实际用户任务决定范围，不夹在自动美化中。外观修改也要保住视觉含义，例如奏法在弧内外、标记归属及续接。

## 需要候选时

本项目提供的用户原PDF／MSCZ保持只读，使用独立副本或原创fixture，不操作当前GUI来做离线试验。其它工程按用户实际授权处理；分析请求不隐含覆盖源文件。详细原生比较方法见[references/native-review.md](references/native-review.md)。

先用已存在的参数和原生属性，固定字体与空间预算，比较少量有理由的方案；不把旧实验数值当通用预设。几何、音乐／记法和整页连带效果分别核对，最终净书图用MuseScore原生渲染。概念预览不代表宿主排版；没有实际渲染则交付建议，不能称已验收候选。

分析不以MCP连接、安装插件或立即打印为前提。需操作当前宿主时，先检查当时真正可用的工具／能力与单位；本库中的接口设想不是可调用工具。发现能力不足先保存具体复现、预期／实际和影响，再按任务范围考虑参数、插件或最小本体方案。不要把普通净书请求扩大成适配开发；用户另行要求开发时，按项目AGENTS和该任务范围推进。

用户只需在有明显、可解释取舍的候选时提供少量直观反馈。微差未显出收益时，由agent继续诊断或保留原样，不反复要求选图；技术核查不转给用户。打印／试奏在准备采用时再核，未做则如实记录。

播放保护须核覆盖范围：mute／solo或不播放的层可能不进入MIDI；必要时另建明确标为诊断的参与播放对照，不悄改最终候选的混音。SVG字符串次序不等也不直接证明几何／像素变化；变换后的坐标、绘图对象与实际图分别核，详见原生保护参考。

跨表连音的数字／括号，经`notation`／`cross-staff`查`TUPLET_CHANNEL_STUDY.md`：先核梁外休止和部分梁范围，再核数字是否归对层、横线是否穿干／混梁。端点范围正确与MIDI保持仍可能留下可读性问题；独立层见`TUPLET_OWNERSHIP_STUDY.md`：无碰撞仍须核归属，必要时单列显示换表点与加线的记法取舍。m97旧端点候选已撤回采用倾向；`M97_TUPLET_TRANSFER.md`的新实曲候选已核，四条加线和本页间距联动须一并说明，视觉选择待回复。

涉及MusicXML导回时，经`beams`／`notation`查`BEAM_EXCHANGE_CLEF_STUDY.md`：逻辑归属、显示staffMove、逐音干向和逐层梁断口分别核；合并后的起音相同仍可能改变轨道、释放与读法。原生副本候选和格式转换各记验证范围。

## 积累经验

任务有新认识时，将情境、阅读理由、例外、原生验证范围和反馈更新到该知识库的相关专题／案例，入口只作必要链接。保存当前来源和宿主，避免抹掉旧基线；原谱图片与教材不加入Git。只将用户实际表达记录成偏好，未复核的其它任务报告标明来源。知识持续更新，不声称这些文件已经永久训练模型。
