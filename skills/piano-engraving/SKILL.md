# 钢琴净书

从演奏者正在辨认的拍组、声部、手、持续、标记归属和导航出发，判断哪里值得改、为什么、代价是什么。也应能有理由保留原排法。不要以参数表、规则数量、页数或几何均匀度替代阅读判断。

## 读取项目知识

本skill与`mcp-musescore`项目的`docs/engraving`知识库共同使用，正文只保存流程，不复制整个库。用随附只读定位器找到实际路径：

```text
python <skill目录>/scripts/engraving_library.py --topic spacing
```

先读返回的`start_here`（本轮已读过则不重复），再选与当前问题有关的专题。项目目录可用`--repo <路径>`明确指定，或沿用`MCP_MUSESCORE_DIR`；目录联接／符号链接安装会定位真实源目录。复制安装且离开项目时，须提供这个库的位置。定位失败应说明缺少哪部分，继续可独立完成的分析，不能声称已读库。

| 当前问题 | 定位器topic | 重点 |
| --- | --- | --- |
| 疏密、两手对齐、光学间距 | `spacing` | 共同时间列、真实占位、光学轴、整行预算及拒绝案例 |
| 主／内梁、休止、切分、换拍 | `rhythm` | 拍组与重音意图；重分梁／时值不能冒充几何美化 |
| 梁坡、符干、线重、加线 | `beams` | 靠梁音头、梁层级、干长及斜向厚度，已有自动处理 |
| tie／slur、端点、续弧、文字通道 | `curves` | 逻辑连接与绘制片段、归属、允许交叉及样式缺省 |
| 力度、发夹、断奏、重音、表情文字 | `markings` | 作用层与时间、动态通道与贴音距离；分别判断省写条件 |
| 颤音、辅助音、装饰小音与收尾 | `ornaments` | 起音／辅助音／收尾、持续／重奏、波线与tie及续行；其它装饰按来源补查 |
| 滑奏、特殊端点、跨行斜线 | `glissandi` | 动作与声部引导、键集合与线形、数值音高与可见含义；原生／交换分验 |
| 声部、手、谱表、踏板、指法 | `piano`、`cross-staff` | 音乐角色不等于voice容器；动作与持续的区别 |
| 变音、附点、连音、装饰音 | `notation` | 适用条件、例外、作用范围与必要说明 |

| 规范查证、官谱定位、宿主差异 | `sources`、`cases`、`baseline` | 用来源和案例定位复查；不把历史结果当当前实测 |

不默认读全部JSON、全书或每篇逐谱笔记。需要具体依据时，从专题链接追到原案例、页／小节、证据和教材章节。Gould长材料的路径、版本及已核页码映射在教材笔记中；不可得的教程、图或视频保持未读状态，不想象其内容。

## 对当前乐谱作判断

看完整系统和邻近上下文，再近看可疑处。PDF提供可见版面，不提供全部voice、手分配、播放或对象范围；OCR、字符码与外框不能独自证明音乐语义。有工程时补读结构和有效样式，区分未保存字段、实际默认与手动覆盖。

遇缩写／脚注先查本谱首次出现、前言和局部限定。作品已有明确定义时采用，不反复让用户解释，也不让通用缩写歧义压过该定义；名称已知、动作范围和播放是否实现分别记录。`WHOLE_SCORE_REVIEW.md`用首处Sost. Ped.(S.P.)更正了旧案例的未知状态，随后仍保留捕捉／释放与辅助弧的核查，不以MIDI相同代替这些判断。

页面问题先分表内、系统间和最外印刷内容；同宽截图不等于相同物理谱高。谱线等距不等于实际白带等宽，而没有贯穿整行的白带也不证明碰撞；按局部轮廓与归属判断，不把外框或空白比例当美观分数。`layout`专题连接`PAGE_HIERARCHY.md`的实际正反例；PDF对象先核真实可见页，完整页外图元也可能混入统计。

把可见事实、规范条件、本次用户选择和待验证解释分开。喜欢新官谱不意味着它每处最优，也不意味着全谱等距、平梁或固定四小节一行。没有本次明确要求时，不擅自套这些样式；用户明确指定的形式仍应遵守并解释实际取舍。极简6/8对照“暂时看不出差别”只表示那一例收益未确认，不形成等距偏好。

报告优先选择阅读影响大的具体位置。说明读者要认什么、当前哪里影响识别、已定位的原因／未知、可保留或可调整的方案和空间代价。音乐本身的密度、必要变音或故意切分不应被当作软件错误。熟悉的节奏不必过度拆分，真正独立的层也不能为了简洁删掉提示。

区分外观候选与记法提议。重分voice／手／谱表、改谱号或时值、拆合休止／tie、增删提示变音、改变拍组可能影响读法；单列解释，按实际用户任务决定范围，不夹在自动美化中。外观修改也要保住视觉含义，例如奏法在弧内外、标记归属及续接。

装饰记号先分主音、辅助音、起音／收尾和连续／重奏。颤音波线交代范围，tie交代不重新起音，单独升降号或括起小头不一定修饰主音或是顺次弹过的grace；不按黑线长度、相同tr字串或MIDI不变自动缩线／合并。跨行只有波线时结合tie与邻层判可读性，书中更推荐的续行提示也不直接变成纠错命令。相关反例从`ornaments`读取。

## 需要候选时

本项目提供的用户原PDF／MSCZ保持只读，使用独立副本或原创fixture，不操作当前GUI来做离线试验。其它工程按用户实际授权处理；分析请求不隐含覆盖源文件。详细原生比较方法见[references/native-review.md](references/native-review.md)。

先用已存在的参数和原生属性，固定字体与空间预算，比较少量有理由的方案；不把旧实验数值当通用预设。几何、音乐／记法和整页连带效果分别核对，最终净书图用MuseScore原生渲染。概念预览不代表宿主排版；没有实际渲染则交付建议，不能称已验收候选。

分析不以MCP连接、安装插件或立即打印为前提。需操作当前宿主时，先检查当时真正可用的工具／能力与单位；本库中的接口设想不是可调用工具。发现能力不足先保存具体复现、预期／实际和影响，再按任务范围考虑参数、插件或最小本体方案。不要把普通净书请求扩大成适配开发；用户另行要求开发时，按项目AGENTS和该任务范围推进。

用户只需在有明显、可解释取舍的候选时提供少量直观反馈。微差未显出收益时，由agent继续诊断或保留原样，不反复要求选图；技术核查不转给用户。打印／试奏在准备采用时再核，未做则如实记录。

## 积累经验

任务有新认识时，将情境、阅读理由、例外、原生验证范围和反馈更新到该知识库的相关专题／案例，入口只作必要链接。保存当前来源和宿主，避免抹掉旧基线；原谱图片与教材不加入Git。只将用户实际表达记录成偏好，未复核的其它任务报告标明来源。知识持续更新，不声称这些文件已经永久训练模型。
