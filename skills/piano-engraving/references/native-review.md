# 原生候选：输入、读法与连带效果

在要生成副本候选时读此页。纯PDF观察和规范解释不需要执行整套导出。对项目记录的受保护原件保持只读；其它任务尊重用户当前授权，不把本页变成新的审批流程。

## 建立比较前提

记录本次输入与哈希、实际宿主二进制、页面／谱间、Music与Text字体及关键有效样式。缺少字体家族标签不等于没有字体，也不意味着显式选了某个家族。未证明二进制对应源码提交时分别记录，不用版本字符串或tag代替构建身份。

共享构建目录的长批次还要核对导出前后宿主是否相同；实际发生替换时，重新建立共同基线，或固定独立运行时并验证它与安装版同输入渲染一致。不把不同二进制的输出拼成参数因果对照；无需为普通只读PDF分析复制运行时。

原路径不能作本项目研究输出。把可编辑文件复制到新的隔离目录，解析MSCZ时按`META-INF/container.xml`找根文件，保留其它ZIP条目。避免批量重置autoplace、偏移、断行或手动梁／弧；它们可能包含用户判断。已保存文件和当前GUI未保存状态也不是同一基线。

研究尽量一次改变一类因素；确需联合调整（如共同列最低宽＋小节stretch）时，明确这是联合候选，不宣称单参数因果。保持原版、候选及不采用的结果，评价完整两手和邻近系统，不只留最好看的小裁图。

## 用实际宿主渲染

本项目已验证MuseScore 3 Evolution的以下命令形状，使用已核实的宿主与新配置／输出目录：

```text
<host> -s -m -c <isolated-config> -r 180 -o <new-output>/candidate.svg <independent-copy.mscx>
<host> -s -m -c <isolated-config> -r 180 -o <new-output>/candidate.png <independent-copy.mscx>
```

不要将其当作所有版本的通用CLI；找不到实际可用宿主时先核能力，不虚构命令。独立导出不操作当前GUI；不要因headless字体替换／缺字而评价原字体不好。导出可能添加页号，PNG可能需合白底。原生SVG用于实际几何，PNG用于视觉核查；VexFlow等概念图不能验证Evolution碰撞与分页。

## 分别检查三种保持

休止改型、居中、显隐或省写前，先读它承接的弧及其它依赖，区分持续独立声部、临时附加层、持键与踏板留声。知识库`SUSTAIN_AND_RESTS.md`中，两条异向Slur同接一个休止；改成整休止后完整MIDI和逻辑连接保持，可见弧尾仍右移约17mm。隐藏版保住曲线也未证明停顿可以省去。对象类型和同端点不能代替人类用途；未知时保留并记录疑点，诊断控制不当作已采用的美化方案。

- **音乐与结构：** 仅改样式／局部几何时，原生XML除明确的字段外应保持；保住音高拼写、起点／实际时长、声部／谱表、连接和范围，以及其它未理解字段。可再导出MusicXML补核，但不能以往返替换原工程。只过滤本次明确预期的布局／样式差异，出现其它差异先定位，不能扩大忽略范围让检查通过。跨格式voice标签可能变化，只有明确验证的映射才可归一化。
- **视觉读法：** 梁分层与短梁方向、休止提示、奏法在弧内外、手提示、踏板持续／重踩、文字归属都可能在播放事件相同时变化。逻辑spanner与跨行绘制段不同，不能按段数合并／拆接。已知自制MusicXML第四层断点导入丢失是反例，见知识库梁干专题。
- **整页与稳定性：** 检查邻小节、行／页数、上下系统、文字与线条连动，必要时原生保存重载再画。固定页数不保证其它对象没动，大范围像素差框也不表示大位移。记录实际位移和核查范围，不把自制例通过推广到任意复杂谱。

不为所有新任务重跑整个历史库；围绕当前改变和未解决风险选择检查。没有做音响、打印、试奏、保存重载或全面碰撞检查时，勿沿用别的候选的通过记录。

同文标记可能分别承担显示与播放：知识库`INTEGRATED_REVIEW.md`的rit.实例只隐藏播放TextLine，保留原StaffText及所有渐慢配置；反例印图相同、MIDI通道事件相同，Tempo事件却改变。遇此类对象要查实际Tempo／控制事件，不能只比Note列表；MusicXML未表示全部原生私有字段，也可能漏掉图面另一来源。逻辑隐藏谱表上的系统对象仍可能显示在可见系统，需联合定位。原PDF和当前工程输出有差别时，分别记录，不把后者的问题和候选冒充前者的修复。

行页候选要读回每系统的小节范围与后续页界；NoBreak等请求写入并保留，不保证超宽组实际合住。页数相同也可能多一系统、使后面几页内容整体移动；局部少一条空谱表未必节省全曲空间。见知识库`PAGE_FLOW_STUDY.md`的实际拒绝案例。判断物理翻页前区分单面／双面起始左右／平板等媒介，再结合速度拍单位、持键／踏板、另一手活动和进入定位；单部休止或教材示例秒数不能直接作安全翻页判据。

音符存在、音头可见、是否播放要分别读取。隐藏头仍可能承担梁的节奏连接，静音长音仍可能提供保持读法；MusicXML父note的`print-object`也不能独自证明头可见，须看`notehead none`等及原生状态。AUTO与显式同值的`headType`可能触发不同共头行为，不按默认等价清理。知识库`UNISON_DOTS_STUDY.md`给出实际工程保留判断及原创对照；MIDI相同、SVG Note元素数量相同，都不保证读法或独立墨迹数量相同。

小数`alter`还可能包含原生tuning，导出八度也可能受ottava状态影响；遇到时回查拼写、微调和音区线，不截成整数或当作多余变音修掉。知识库`SECONDS_OWNERSHIP.md`给出本机实际例和附点归属候选；本轮外观范围不隐含改调音／音高。

## 量对对象

未连梁先读书写音值、真实Tuplet的比例／基准值／范围、显示省略与演奏解释。知识库`RHYTHM_READING.md`纠正A109后页旗尾的误判：四分＋八分省3不能像连续普通八分直接合梁，拆长音会增加头和tie。原创原生两版实际起音与完整MIDI相同仍有阅读取舍；A074十六分swing等式又属于不同解释层。PDF先回查开头、simile和局部拍数，不把不合普通时值算术直接当错误；工程省数字保留真实组，不按全谱一个swing开关替代，也不混入无声的自动记法重写。

指法同时读取父Note、富文本和实际动作范围。替指连接、同指多音符号不是普通Slur／手接管括形；单父Note也未必覆盖全部相关音。知识库`FINGERING_STUDY.md`保留合理堆叠，拒绝贴近却碰小节线和只留数字的版本；19个指法对象仍可丢掉含义。实际MusicXML往返会把本例的符号名称印成字母，且引入其它布局／播放配置；原生重载保留，故不得据交换文件音符／指法数量相同替换源工程，也不将附加播放变化归因于指法本身。

连音要分别核显示数字、完整比例／基准音值、嵌套结构和实际跨度。MusicXML每音的time-modification可能已经是各层的合成值，不能又乘一遍父比值。知识库`TUPLET_READING.md`中，省显示仍保留13个真实Tuplet；变化处和嵌套范围继续明确，外层括号用局部端点避开内层5。完整MIDI相同的全隐藏版仍被拒绝。两原生版的m4 MusicXML整树相同而括号图面不同，也说明该输出不能独自证明局部几何保留。

提示变音要分清源音高／拼写、AUTO／USER、括号身份与读者确认需要，不按显示符号总数或前一个同MIDI音去重。新行tie上补普通变音，可能使后面的自动变音省去；读回后续可见符号，保住未改的pitch、tpc、tuning、连接和实际反复路线。第一／第二结尾、D.S.／Coda不能只按纸面顺序延续状态；未知时提出疑点，不擅自补改。知识库`ACCIDENTAL_CONTEXT.md`包含同系统控制、跨行与简单反复的原生对照，未证明复杂导航自动处理已实现。

共同起音看逻辑时间列和正常侧音头，不以二度和弦整对外框中心拉齐；变音／附点的必要错列与光学补偿单独分析。符头绘制原点、真实墨迹框和字符框是不同量。

和弦的干线全长包含穿头部分，应另看靠梁音头到梁的长度；斜梁竖向投影厚度与垂直于梁的厚度也不同。单位由物理尺寸／viewBox／实际sp校验，不能把所有SVG都按本次5单位=1pt换算，或把插件spatium数字直接当mm。导出坐标有舍入，容差应有量化精度依据。

外框相交只筛疑点，不是通用碰撞判据。发夹穿干、梁穿另一部干、弧跨休止各有条件；检查实际墨迹和所属层，不能优化成所有对象零交叉。

## 交付与后续开发

交付少量有价值的位置及原生候选，解释改善哪种阅读、代价和仍未知处；可选择保留。技术变得更均匀但用户看不出差别时，记录感知收益未确认，继续找有理由的问题。

若现有控制无法保住需要的记法或布局，保存可重复输入、当前宿主、最小改变、实际差异及可接受替代的代价。先判断参数／插件能否解决，再为必要的本体接口形成需求；不将文档中的设想当已实现能力。
